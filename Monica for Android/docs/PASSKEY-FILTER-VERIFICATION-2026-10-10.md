# Passkey 数据库筛选返回回归验证（2026-10-10）

## 问题与修复

Passkey 列表原先在每次进入页面时，以设置尚未加载的默认“全部”完成一次性恢复，再把该值写回设置。已在公共 API 32 虚拟机复现：选中本地库并点击条目，列表离开组合后重新进入，Bitwarden 测试条目重新出现。修复前的真实列表测试在 `assertDoesNotExist` 处失败，日志保存在工作区 `.codex-tasks/passkey-filter-20261010/main-baseline-device.log`。

筛选状态和待完成的保存操作现由已有 PasskeyViewModel 持有，页面只读取状态；仅用户选择触发保存。初始化读取不能覆盖用户已经作出的新选择。自动同步继续等待筛选恢复完成。沿用现有筛选编码，保留数据库 ID、文件夹 ID 和 KeePass group UUID。

## 验证

| 构建 | 相关单元测试 | 设备测试 | Debug 及测试包构建 |
| --- | --- | --- | --- |
| 普通版 | 52 通过 | 9 通过 | 通过 |
| F-Droid | 52 通过 | 9 通过 | 通过 |

- Passkey 实际列表选择本地库，连续三次点击条目、离开列表、返回；检查未选中的 Bitwarden 条目不出现，并验证新 ViewModel 恢复保存的选择。
- Bitwarden 与 MDBX 文件夹各连续三次往返；其他文件夹和本地条目不混入，保存值不变。MDBX 测试使用隔离的 Room 元数据，没有打开或写入真实 MDBX 文件。
- 持久化覆盖本地库、Bitwarden 库及文件夹、KeePass 库及带 UUID 的分组、MDBX 库及文件夹；验证启动时立即选择本地或“全部”不会被初始读取覆盖。
- 普通验证器通过条目菜单进入编辑流程并连续三次返回，重新创建 ViewModel 后仍保持本地库筛选；此路径测试通过，无需修改其产品代码。
- 既有 Passkey 扫描菜单，以及验证器标准列表／磁贴布局的选择、二维码和删除确认测试通过。

设备为已运行的公共 AVD `Monica_Issue136_API_32`（emulator-5554）；直接复用，本任务未启动或停止 AVD。新增测试使用隔离的内存数据库，并恢复测试前的筛选设置。列表测试使用真实列表和条目点击回调，以测试详情占位页触发列表销毁／重建；没有声称验证系统 Passkey 登录或真实云端同步。

普通版最终结果合并完整测试组中已通过的八项与验证器测试修正后的单项复测。初轮曾发生一次保存等待超时和截图失败，未更改产品代码的单独复测及后续完整组均通过。验证器测试修正了远端条目缺少 cipher ID、以及误把卡片点击当作编辑入口的问题。最终设备运行与构建分开，临时保持屏幕亮起，并在结束后恢复原超时设置。
