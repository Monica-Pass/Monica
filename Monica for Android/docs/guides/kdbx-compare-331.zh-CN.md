# 离线比较与选择性合并 KDBX 数据库

适用范围：Monica Android 1.0.331 开发版本。原比较引擎的验收见 [验收记录](../verification/kdbx-compare-331.md)；选库、认证复用和动画的最新验证见 [交互改进记录](../verification/kdbx-compare-experience-331.md)。

此功能从两份 KDBX 中读取内容，先展示差异，再按你的选择生成一个新的加密 KDBX。比较不会替换两个来源库，也不会把结果自动绑定到原库的云同步位置。MDBX、Bitwarden 和 Monica 本地 Room 库不在本次范围内。

## 准备两份数据库

1. 打开 **本地 KeePass 数据库**，选择数据库，进入 **管理数据库内容 → 更多选项 → 比较与合并**。
2. 确认“当前数据库”，再选择“另一个数据库”。两侧均可打开选库面板，选择 Monica 中的内部／外部 KDBX；列表显示位置和认证状态。也可通过系统文件选择器选择 `.kdbx` 文件。
3. Monica 中仍有有效原生认证会话的库会显示“使用当前认证”，无需重复输入密码或密钥文件；认证过期、锁库或会话已释放时需重新输入。系统文件选择器选入的文件总是需要本次凭据。需要密钥文件的库可分别选择正确文件；仅使用密钥文件的库可将密码留空。
4. 点击 **比较数据库**。只有文件与必要附件已在本地可用时，整个过程才能离线完成；该入口不会自动下载缺失的远端库。

当前实现接受 KDBX 3.1、4.0、4.1，但一次比较的两份输入必须是相同的格式版本。不同版本组合会明确阻止合并，需要先用可信客户端另存为相同版本后重试。旧 `.kdb` 文件和硬件挑战响应解锁不属于此入口的支持范围。

## 审阅差异

比较结果提供 **全部、差异、需要选择** 筛选。相同身份的条目以数据库内 UUID 关联；标题相同并不等于同一个条目。不同根身份的独立数据库会保留独立分组，不会凭名称自动去重。

可审阅内容包括条目字段及保护状态、分组位置与顺序、标签、自动输入配置、历史版本、附件、图标、数据库元数据及删除记录。没有条目引用的附件数据会单独列出，不会悄悄丢弃。密码等字段默认隐藏，点击 **显示字段值** 后才显示。

对需要处理的项目，可以选择：

| 操作 | 结果 |
| --- | --- |
| 采用当前版本 | 新数据库采用当前库的该项目版本。 |
| 采用另一版本 | 新数据库采用另一库的该项目版本。 |
| 保留双方 | 在能安全复制身份的条目上保留两个独立项目；不是所有项目都会提供此选项。 |

仅存在于一边的条目默认保留。若主动选择“不存在此项目”的另一边，该条目会被排除在新结果之外；原库不变。匹配条目采用一边当前版本时，会保留可用的双方历史及被替换的当前内容，避免仅凭较新的时间戳丢掉另一版本。

Passkey、含有不透明绑定信息的项目，以及无法可靠重写引用的项目，不提供“保留双方”的身份复制。可以安全保留的完整凭据仍按整个条目处理，不拆开拼接私钥字段。

## 删除记录与依赖

“一边没有这个条目”不自动代表删除。只有库内明确的删除记录会显示为删除相关操作；采用删除记录时，相关条目、分组和引用的选择也必须一致。

如果选择组合会造成文件夹循环、缺失父分组、缺失附件或图标、引用失效、引用指向改变或循环引用，生成结果会停止。请调整相关选择，或保留原库继续使用。无法理解的扩展数据也不会被当作空白内容写回。

数据库的名称、描述、默认用户名、回收站、模板及其他元数据单独审阅。数据库密码、加密算法和密钥派生设置不作为普通条目拼接。

## 生成并保存新数据库

1. 处理完待选择项目后，点击 **预览并保存**，检查采用各方内容的数量。
2. 为新数据库输入并确认一个密码。**新结果仅使用这个密码，不继承输入库的密钥文件。** 加密算法、密钥派生参数和文件版本沿用“当前数据库”。
3. 点击 **生成并保存**。程序先在私有临时位置生成加密文件，重新打开并验证原生内容，再打开系统保存位置选择器。
4. 选择新的文件位置和名称。已有非空文件不能用作目标，两个输入数据库及密钥文件也不能作为目标。建议保存到本机目录或自己控制的存储位置；如果主动选择云文档提供器，文件传输行为由该提供器决定。
5. 显示“已保存并验证”后，可通过正常的添加 KDBX 流程打开结果，用新密码检查需要的条目。新库不会自动替代原库，也不会自动建立云同步配置。

不要根据文件数量或“生成完成”的中间状态判断保存成功；应以最终保存与验证结果为准。取消保存、写入失败或验证失败不会替换输入库，失败的目标文件可能保留为空文件。

## 中断与不支持的情况

- 退出比较页面、锁定应用或普通后台切换后，需要重新比较。系统选择文件／保存位置期间采用专门的受控流程。
- 审阅期间来源文件或注册信息发生变化，需要重新读取比较，旧审阅结果不能继续覆盖新数据。
- 不同版本、独立库之间 UUID 冲突、无法保留的 XML／头部扩展、不能唯一解析的引用等会明确阻止相关操作。
- 当前比较对输入大小、XML 大小和密钥派生资源需求设有限制。达到限制时不会自动降低原库的加密参数。
- 这不是损坏数据库修复工具，也不能代替原密码或找回永久丢失的密钥文件。
