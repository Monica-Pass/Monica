# 时间线重设计：看清变化，找回需要的内容

状态：设计方案，尚未接入 Android 生产代码。基线为普通版 `481f4a1aed6dc8d25fd685f0fb840ade1df4a413`、F-Droid `548a396ff7089b603161a098ca6ccdb1746bd039`。两版均保持未发布 1.0.329。本方案不包含折叠屏改造。

## 1. 页面要解决的问题

用户进入时间线，应该能找到刚才做过的操作，知道影响了哪些项目，并在有真实恢复材料时找回内容。首页保留“时间线”名称，不做统计仪表盘。

典型问题：

- “刚才修改的是哪个账号的密码？”显示项目名、账号和变更字段。
- “误删了验证器怎么办？”显示是否仍在回收站、保留期限和恢复入口。
- “这次同步到底改变了什么？”显示实际上传、接收、删除、冲突及失败，区分检查次数和项目数。
- “恢复会不会覆盖后来的修改？”恢复前展示当前值与目标值，重新验证当前版本；冲突时保留后来的修改。
- “一个项目有多个账号，为什么出现多条？”一次用户操作生成一个操作事件，账号变更是其子项。

现状证据见 [源码审查](../verification/timeline-redesign-329-audit.md)。下文所有“新版”行为均为设计要求，不代表现有应用已经支持。

## 2. 信息结构

### 时间线首页

顶部使用现有 Material 3 Expressive 大标题；搜索按钮和带文字的回收站入口。二级区域为“变更 / 可恢复 / 同步”三个标签，下面显示“全部密码库”和时间范围筛选。进入时默认“变更”。

| 区域 | 展示内容 | 规则 |
| --- | --- | --- |
| 变更 | 新建、编辑、移入回收站、永久删除、移动、导入、恢复；同步接收的实际项目变更 | 按真实时间倒序，按自然日分组；标注来源与操作发起方 |
| 可恢复 | 有本机恢复材料、仍在回收站、存在可定位原生历史的操作 | 表示有恢复候选；行内用“已保存旧值”“在回收站”“需解锁检查”等事实标签，打开后验证可执行性 |
| 同步 | 每次同步的结果、可操作失败、待处理冲突 | 成功且零变更的自动检查按密码库和自然日折叠，失败及冲突不折叠隐藏 |
| 回收站 | 现有已删除项目管理 | 复用原有入口和恢复执行器；时间线删除详情可定位同一个项目 |

一次操作卡片有四层信息：项目或批量操作名称、实际动作、变化摘要、时间与来源。示例：

> 星河邮箱 · 已修改
> 个人账号的密码、备用账号的备注
> 本机密码库 · 此设备 · 19:18　已保存旧值

不再出现“同步 24 个 Bitwarden 同步”。同步示例：

> 工作账号 · Bitwarden
> 上传 2 项，接收 1 项，1 项上传失败
> 18:40　查看失败项目

“上传 2 项”和“接收 1 项”是方向计数，同一个项目可出现在两侧；不得直接相加称作 3 个不同项目。需要总数时按稳定项目身份去重。旧日志没有身份清单时只显示原有方向计数，不伪造项目明细。

### 搜索、排序与分页

- 搜索覆盖已授权可读的项目名、账号标签、字段名称、操作类型、密码库名称；不搜索密码、验证码种子、笔记正文或附件内容。
- 数据源先按来源、日期、类型筛选再分页，不先取 100 条再过滤。游标至少包含 `(occurredAt, eventId)`，同毫秒有稳定顺序。
- 聚合只接受同一 `operationId`，或明确标记为零变更自动检查的同库同日事件。不同库、不同用户操作不因相邻或同类型合并。
- 自然日分组使用当前时区的日历边界；跨年显示年份，不能用固定 24 小时推算昨天或本周。
- 时间记录不齐、库未解锁、离线、不支持读取、真正没有操作分别显示，不用统一空列表代替。
- “此设备”是执行或观察来源；同步事件不得把本机下载时间冒充远端编辑时间。无法知道远端作者时显示“从 Bitwarden 接收”，不猜测人或设备。

## 3. 操作详情

普通详情进入全页，保留返回位置；避免在长字段差异、多个账号和大字号时堆叠多层底部弹窗。轻量筛选可继续使用底部弹层。

### 编辑

顶部显示操作发生时的项目名、当时的密码库、操作时间、来源。项目后来改名可补充“现名”，不能把当前标题冒充历史标题。账号按稳定身份分组，字段使用本地化名称；重复自定义字段也要区分实例。

每个变更块依次展示“修改前”和“修改后”；恢复预览另展示“现在”和“将恢复为”。旧版本、修改后版本、当前版本是三个不同状态。

- 密码、账号值、备注、自定义内容默认隐藏，复用应用现有验证和显隐策略；未知字段按敏感内容处理。
- 只有记录了变化的字段才出现。没有旧值时写“未记录旧值”，解析失败写“记录暂时无法读取”，不显示“无变更”。
- 多账号项目一次保存只占一条事件；展开显示“个人账号 / 密码”“备用账号 / 备注”等变化。不能按 Room 行数称为多个项目。
- 可验证的完整项目旧版本才提供“另存历史副本”。仅有部分字段旧值时提供对应字段恢复或查看旧值，不把当前项目拼上旧字段称作完整旧版本。
- 字段恢复按依赖组选择：账号与密码配对、引用、绑定内容等必须同时恢复的部分不可拆选。用户看到的是内容分组，而非内部字段路径。

### 删除

必须区分“移入回收站”“永久删除”“清空回收站”和“旧记录未注明方式”。

| 当前核验结果 | 详情说明 | 操作 |
| --- | --- | --- |
| 仍在本机回收站 | 显示删除时间、原位置、清理日期；未设置自动清理就直接说明 | 预览恢复 |
| 远端删除已排队 | 显示“本机已移入回收站，等待同步” | 检查恢复，复用远端队列规则 |
| 已恢复 | 指向对应恢复事件和当前项目 | 打开项目 / 查看恢复记录 |
| 已确认永久删除，且材料已清理 | “已永久删除，没有可用恢复数据” | 查看备份入口（如存在），不宣称备份一定能恢复 |
| 旧日志缺失方式或材料 | “此记录未保存删除方式和恢复数据” | 查看回收站；无法定位时不自动选中相似标题 |
| 原库锁定、不可读、未同步 | “需要解锁原密码库后检查”或相应原因 | 原有解锁 / 重试入口；不能宣称已永久删除 |

恢复期限来自该材料的实际策略与到期时间。不能把本机 30 天套到 Bitwarden 服务端、KeePass 回收站或手动保留的 MDBX 快照。

### 批量操作

一次导入、移动、复制或恢复占一张卡，展开逐项目结果。计划 6 项、已成功 4 项、失败 1 项、未执行 1 项分别计数。跨库不能用一个“成功”或一个 `isReverted` 掩盖部分完成。

撤销移动前检查每项当前所在位置、身份和修订。撤销复制涉及删除副本：副本随后被编辑、增加附件或被引用时不自动删除。初版不提供没有完整证明的跨库一键撤销。

## 4. 恢复流程

```text
查看详情 → 读取恢复材料 → 检查当前项目及原生修订
           ↓ 不可读/过期/缺失        ↓ 可执行
           说明原因                恢复预览
                                     ↓ 确认
                            再次核对会话、材料、修订
                                     ↓
                       保存恢复前版本 → 执行 → 记录结果
```

预览必须回答：恢复哪个项目或哪些字段、恢复到什么时间、写入哪个密码库、会产生哪些同步动作、哪些项无法恢复。确认按钮使用具体动作，例如“恢复 2 处修改”“恢复验证器”“恢复 4 个项目的位置”。

确认之后出现锁定、后台、取消或新修订，计划失效；不得继续使用旧权限执行。保存恢复前版本失败时终止恢复，不先覆盖再补备份。

冲突处理：

1. 变化字段已被再次编辑：停止原位恢复，展示冲突字段。
2. 仅不相关字段后来变化：有经过验证的字段级比较和原子写入能力时，只恢复选定字段；初版保守拒绝亦可，但必须说明。
3. 有完整、可独立解码的项目旧版本：允许“另存历史副本”，明确目标为本机新项目；生成新项目/账号/字段身份，处理内部引用，清除原同步身份，不复制 Passkey。
4. 只有部分旧值：允许查看已保存的值，不开放伪完整副本；没有恢复材料不能生成恢复按钮。

恢复是一条新的操作，关联原事件。原事件保持事实不变；重复点击和进程重试使用同一执行身份，不能生成重复副本。“恢复一次后再点就是重做”的隐藏开关删除，重新恢复需要新的明确预览。

对异步远端写入区分“本机已恢复，待上传”“服务器已确认”“结果待确认”“失败”。网络超时后先查询队列及远端状态，不盲目重发创建或声称成功。跨库只保证各原生提交范围内的一致性，逐项显示部分结果。

## 5. 各来源的能力边界

| 来源 | 当前可复用能力（静态确认） | 新时间线接入方式 | 明确不承诺 |
| --- | --- | --- | --- |
| 本机 | 回收站；部分类型和字段的加密前后值 | 接入真实回收站；新增完整项目版本及字段级恢复计划 | 旧日志补出从未保存的内容 |
| KeePass | 原文件 Entry history、带目标校验的历史恢复、原生回收站 | 定位 Entry UUID 和历史指纹，复用 change set 与来源修订保护 | 通过 Room 行回写假装原生恢复；跨文件原子回滚 |
| MDBX | 原生 commit history/diff、revertCommit、managed snapshots | 绑定 vault/object/commit，先跳转已有原生历史；计划和保护验证完成后再接统一预览 | 用 Room 镜像恢复；把整库快照恢复包装成单项目恢复 |
| Bitwarden | 密码历史与已有删除/恢复队列、冲突处理 | 历史密码只标记为密码历史；删除恢复走原队列和真实服务器确认 | 从 passwordHistory 重建完整项目；仅 GET 后就宣称消除了远端竞态 |
| Passkey、硬件密钥 | 现有专用管理与源数据 | 时间线说明操作，提供可用的专用管理入口 | 普通版本快照复制私钥或任意撤销注册/删除 |
| 备份 / WebDAV | 现有备份和恢复入口 | 展示备份结果，定位对应备份；进入专用预览 | 点击同步事件即整体倒退数据 |

第一批上线应覆盖所有来源的清楚记录、正确状态和跳转。只有通过原生读写及冲突回归的来源才开启统一恢复按钮，不能把“数据库里有一行 snapshot”视为可恢复资格。

## 6. 记录层设计

采用“操作事实 + 恢复材料 + 运行时能力检查”三部分。继续使用现有数据库和安全封装，不自建整套 event sourcing，不改密码/KDF/库格式。

建议新增 V2 schema，保留旧日志兼容读取：

| 数据 | 关键内容 |
| --- | --- |
| OperationEvent | 随机 eventId、schemaVersion、operationId、parent/causeId、明确 action、origin、occurredAt/observedAt、outcome |
| OperationTarget | 来源类型和稳定 vault/native/project 身份、账号稳定 ID、执行前后修订、逐项结果 |
| EncryptedDetails | 当时的项目/库/账号名称、字段差异、必要的来源说明；解锁后才可读取 |
| RecoveryMaterial | 加密完整项目或有明确覆盖范围的字段旧值；或原生历史引用；完整性清单、到期时间、大小、schema |
| RecoveryExecution | 计划摘要、期望修订、幂等执行 ID、逐项完成状态、确认后的新事件引用 |

字段键使用稳定代码和稳定实例身份，不用“密码”等翻译文本作协议，也不用列表下标代替账号身份。项目快照包括账号与密码对应、内容块、普通/隐藏自定义字段、UUID/保护位、附件、绑定及未知字段。不能保存完整材料时降级为部分字段记录，并标明覆盖范围。

附件应复用已授权的加密 blob 和引用计数，恢复期间保证引用仍可读，校验摘要；不把明文路径或大量二进制塞进日志 JSON。无法保证附件/外部引用完整时，不开放完整副本或整项目回滚。密码哈希等可被离线枚举的信息也不得明文放入比较索引。

### 写入一致性

- 本机业务变更、事件及对应恢复材料在同一授权事务内提交，不能沿用独立 IO 协程“稍后补日志”作为可靠恢复依据。加密准备在后台执行，提交前再次核验会话与原版本。
- 多账号保存按用户操作分配 `operationId`，只有各子项提交成功后才报告成功；失败不制造成功事件。
- 原生文件、Room 与云端之间不宣称存在一个原子事务。使用现有 provider 写入结果、稳定操作身份和可恢复的执行状态；源提交成功但日志未完成时可核验补记，补记不能重放业务操作。
- 同步接收以真实来源修订去重，关联同一同步会话；本地上传确认更新传输状态，不再制造一条重复“编辑”。明确区分远端已改动与仅重复下载。
- 所有写入口（普通编辑、自动填充、批量、导入、回收站、原生历史恢复、同步应用）在 Repository/provider 边界覆盖，UI 不单独维护另一套事实。

### 安全与保留

- 标题、账号标签、差异、恢复材料使用现有受控加密服务；列表只解密当前页需要的内容，详情按需读取。锁定/后台清空页面明文和能力计划，迟到结果不可发布。
- 本机加密编辑快照暂沿用 30 天策略；期限到达后读路径立即拒绝恢复，不能依赖下一次编辑触发清理。原生历史遵守各库实际策略。
- 删除日志与删除恢复数据是不同操作。未来若提供清理入口，必须显示分别影响什么；永久删除项目时一并清理其本机可恢复材料、附件引用与派生索引，保留无内容的操作事实。独立用户备份不能被悄悄删除，也不能声称已被清除。
- V2 不迁移删除旧日志，不替用户调整回收站天数。零变更检查的折叠首先是展示优化；新的容量/保留上限上线前另作策略说明。
- 新增保留或显示设置时必须使用共享 `Setting` 定义，自动进入设置搜索。
- 初版时间线为本机活动视图，明确区分“此设备记录”和“原库历史”；不承诺各设备的完整统一审计。恢复材料继续不混入现有普通日志备份，备份/导出说明这一边界。

## 7. 旧记录兼容

旧日志通过单独 adapter 读取，不重写源 JSON。能够解析的字段变化如实显示；缺失原因分为未记录、已脱敏、材料到期、读取失败、来源待解锁和格式不支持，不能统一 emptyList。

旧敏感标题当时已被擦成 `TYPE#id`，只可从当前授权数据补充当前名称并标注；项目已消失则使用通用名称。不能从 `Bitwarden Vault #6` 这样的展示字符串当作可信身份恢复。旧同步仅有计数时明确“此记录未保存项目明细”。

旧字段快照可继续提供其确实覆盖的恢复，但执行层也必须检查 provider、当前修订、字段完整性和有效会话。原来的 TODO 分支按钮不接入新版。批量恢复的旧载荷在完整性/修订无法证明时只读。

## 8. 视觉与交互规范

- 继续 Material 3 Expressive 动态色与系统字体。青绿色表示主要操作，警示只用于冲突和失败；不用每类操作一套渐变。
- 标题 28–32sp、项目名 16–18sp、摘要 14sp、时间 12–13sp。使用系统 Roboto / 中文系统字体，时间用等宽数字特性；不用自带装饰字体。
- 16dp 页边距，40dp 图标容器，至少 48dp 点击区；同日事件用轻量时间轴和连贯容器组织。卡片高度随摘要和字号增长，不做固定两行裁切关键结果。
- 底部主按钮随详情内容滚动或占独立安全区，不遮挡内容。恢复确认使用单独页面，显示目标和具体后果。
- 320dp 与 2 倍字号下保持单列，差异上下排列；深浅色、对比度和屏幕阅读器状态标签必须可读。无动画设置下立即切换；锁定立即隐藏，不等待退出动画。
- 可恢复、过期、冲突同时有文字和图标，不能只靠颜色。恢复结果用可访问状态播报；返回保留筛选、滚动和选中的事件。

本地可编辑 M3E Canvas 与交互原型位于忽略的 `docs/design/timeline-redesign-329/`；只使用合成项目。可运行的网页原型用于体验信息结构与恢复预览，不连接应用数据库，不代表 Android UI 已验收。

## 9. 落地顺序与验收

1. **记录与只读界面**：V2 事件/旧 adapter、分页和查询、操作级聚合、同步降噪、删除详情与原生入口。确认旧日志不被修改，100+ 次空同步不会挤掉编辑记录。
2. **本机真实恢复**：同事务快照、完整项目/字段覆盖清单、预检和确认、冲突/幂等/恢复事件；接入回收站。多账号、附件和未知字段必须实际往返，不能只测卡片。
3. **原生来源**：KeePass 历史与 MDBX commit 对应关系、原生修订检查、Bitwarden 排队/远端确认/失败；跨库逐项结果。每个 provider 单独通过才能开启相应操作。

最低测试清单：

| 场景 | 验收要求 |
| --- | --- |
| 1 个项目 3 个账号一次编辑 | 1 个事件；准确定位账号与字段；原存储身份无变化 |
| 100+ 空同步、2 个库相同标题 | 不丢用户变更，不跨库误聚合或误恢复 |
| 编辑后继续编辑、外部修订、点击预览后再修改 | 明确冲突，不覆盖后续数据 |
| 回收站恢复、已永久删除、锁库、到期 | 状态及按钮正确；未知不冒充不可恢复 |
| 附件、历史、重复字段、未知类型和绑定项目 | 完整保存或明确只读，不产生精简副本 |
| 多选恢复、部分失败、断网、超时、进程退出 | 逐项结果真实；重试无重复写入；同库事务边界明确 |
| 确认前/执行中锁定、后台、取消 | 无迟到明文和未授权写入；已提交结果可核验 |
| 恢复旧版本、再次恢复、另存副本 | 新事件可追踪、当前版本保留、身份/引用正确 |
| 旧 schema、损坏 JSON、脱敏载荷、材料缺失 | 不显示“无变更”，不出现无效恢复按钮 |
| 320dp、2 倍字号、深浅色、中文英文、读屏 | 所有主操作可见可达，敏感值默认隐藏 |

存储/迁移实施需另按 AGENTS.md 完成同签名 Release 覆盖升级、旧库读取和真实 provider 回归。本轮只有设计与源码审查，没有执行这些 Android 验收，也没有改变用户数据库。
