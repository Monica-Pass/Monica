# LAN IP autofill — unreleased 1.0.324 (main)

Valid IPv4 and IPv6 addresses can be recovered from the existing browser address-bar nodes when Android does not report a website host. Expanded/bracketed IPv6 forms normalize to the same complete host, and the generated fill URI brackets IPv6 correctly. HTTP addresses with ports are supported for host matching. No DNS resolution or network lookup is added.

Default IP matches require the complete address. Base-domain, subdomain and numeric loose-match heuristics cannot recommend another device's IP credential. Explicit user URL rules retain their semantics; host/base rules normalize IPv6, and exact/prefix rules still require the full URL information they need. Host matching follows the existing per-host semantics: it does not invent missing browser ports, paths or schemes, or distinguish ports when the framework supplies only a host.

Reported website hosts and the accessibility browser-address cache share validation. Rejected same-browser address updates revoke the previous snapshot. Native hybrid applications serving their own WebView UI from IPv6 loopback `::1` retain application bindings, as with `localhost` and `127.0.0.1`; known browsers retain the loopback website origin. Existing address-bar identifiers/depth restriction, form/window boundaries, originless-browser package restrictions, authentication, locks and secret storage remain in place. The patch adds no production permission, dependency, visible UI or string resources. AndroidTest alone allows cleartext for retained explicit HTTP diagnostics.
