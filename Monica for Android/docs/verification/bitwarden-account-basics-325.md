# Bitwarden 新设备邮件重发与账号验证短语 — 1.0.325

2026-11-05，**两版构建、62 项 JVM、28 项 API32 设备方法及代表界面验收通过**。本批覆盖 AUTH_A03 新设备邮件验证码重发与 AUTH_A12 账号验证短语，不代表 Bitwarden 后续组织、硬件认证、SSO 或企业功能已完成。普通版与 canonical F-Droid 保持未发布 1.0.325，versionCode 分别为 12、32。

## 实现与安全边界

新设备验证弹窗增加明确点击的重发按钮，使用当前登录挑战的邮箱、密码派生证明、服务器、请求指纹与 TLS 设置。官方协议是 `POST accounts/resend-new-device-otp`，JSON 只有 `Email`、`MasterPasswordHash`，不添加访问令牌；自托管 API 基地址组合为 `/api/accounts/resend-new-device-otp`。它与普通邮件二步验证的 `two-factor/send-email-login` 独立，成功发送请求不等于登录成功，提交验证码仍使用 `newDeviceOtp`。

发送状态、结果与至少 30 秒的单调时钟倒计时独立管理。并发和快速重复点击不发送请求；HTTP `Retry-After` 秒数或日期可延长等待。错误只显示固定分类，不读取或记录可能回显证明的响应正文。404/405 明确表示服务端不支持，不回退到普通邮件二步验证接口。仓库在请求前后验证原认证代，网络请求期间不持有认证锁。

取消、替换登录、离开页面与全局锁定撤销重发请求及迟到结果；取消、离页和锁定清除原临时挑战。切去邮箱仅撤销发送与反馈，原进程内挑战和剩余冷却时间保留；回到前台只有原全局锁代仍有效才生成新的发送授权，不自动重发。不可取消请求的迟到完成属于 JVM 控制器证据；设备用例另覆盖真实 Activity 停止／恢复、按钮取消及全局锁定，不把两者混称为同一种测试。

账号设置增加只读验证短语和复制入口。身份来源是通过既有会话、账号与 security-stamp 检查的 profile；从已有 type-2 加密 RSA PKCS8 私钥材料验证并提取公开 SPKI，不生成新身份密钥。只缓存用原账号密钥封装的公开身份，绑定规范化服务器、邮箱、用户 ID 和 stamp。profile 未提供私钥时保留已验证缓存；明确无效材料清除旧缓存。普通锁定保留封装数据供正常解锁后读取，退出或会话失效清除对应身份缓存。

短语在本地根据用户 ID、公开 SPKI 和固定 EFF 7,776 词顺序派生；仅打开短语不会发起网络请求。读取、发布与复制都核对账号、密钥实例、应用／密码库锁代与前台生命周期。初始 profile、预检与完整同步入口均传入请求开始时的会话约束；迟到响应不能替换、清除或撤销新会话。私钥输入字节数组在处理后清除；不宣称 JVM 内所有不可变中间对象均可立即擦除。

界面短语仅在现有连字符后加入显示用换行机会，避免词中断行；复制仍使用无隐藏提示字符的规范短语。短语词表保持英文协议顺序，周边说明、操作和错误覆盖 18 个资源配置，含两种葡语地区语义。

## 失败历史与修正

1. 初次普通版 JVM 61 项中 57 通过、4 项 IdentityStore 失败；诊断重跑仍为同 4 项。新增直接解密／公开 SPKI 断言定位到 Android provider 未实现 `RSAPrivateCrtKey` 接口的假设。改为已有 BouncyCastle 的 PKCS8 RSA 公开参数解析，仍拒绝非 RSA、短 RSA、无效指数及未认证密文，并增加旧缓存不得保留的回归。最终候选的 62 项包含该新增方法，不能把前两次执行叠加为更多不同用例。
2. 初次设备 28 项中 25 通过、3 失败：短语标题语义溢出、锁定／解锁后旧复制回调重新有效，以及葡语重发测试未找到预期文字。复制回调改为捕获标量代数并在离页／关闭时撤销；葡语夹具改为配置和恢复真实 Activity 资源，因为独立 Dialog 使用宿主 View 的 context，单改 CompositionLocal 不会改变窗口语言。
3. 第二次设备 28 项中 27 通过、1 失败。真实大字号下，指纹标题显示宽 861、高 98，而语义段落宽为 954；完整 26 字、实际行右界 860.5742、无省略和高度溢出，并经截图观察确认可见。此后指纹断言改为完整字符、无省略／截断、逐行及非空白字符几何与可见边界核对，保留原 `hasVisualOverflow` 为诊断。重发用例首轮尚未走到溢出断言，没有本轮误报证据，因此其原 `hasVisualOverflow` 门槛始终保留，并附加细分诊断。
4. `text-layout-full` 候选设备 28 项通过后，截图仍发现英文单词中间换行。随后才增加显示用断行提示与断行位置断言，形成 `readable-full` 候选；先前通过不替代后续候选验证。
5. `main-readable-device` 虽有 28 项通过，实际仍是 seq03 旧包：安装 seq04 时 ADB 自动重启后设备尚在授权，安装失败，但同一 shell 继续使用旧安装回执执行测试。该结果及原日志保留并明确排除；seq04 普通版候选使用独立安装确认后的 `readable-installed` 验证。seq03 主包 `02bb2ea6…`／测试包 `0b031521…` 不得作为 seq04 或后续新包的证据。
6. 独立安装后，两版 `readable-full` 候选各 28 项通过且 APK 摘要门核对通过，但 root 查看普通版英文大字／缺失身份截图时发现白屏，不能将其计为视觉验收。相同 APK 单跑大字方法 `main-visual-isolated-large` 为 1 项失败，异常为 `performMeasureAndLayout called during measure layout`，堆栈指向旧 Compose Unconfined 测试帧调度的测量重入；相同包单跑缺失身份方法 `main-visual-isolated-missing` 为 1 项通过，新图正常，FD 对应两图也正常。这些结果分别保留，不把后来的单项通过覆盖白屏或调度失败。随后仅将指纹测试入口改为已有 Compose v2／StandardTestDispatcher，等待弹窗焦点和真实帧提交，保存窗口诊断并拒绝单色白屏采样；原 9 个测试正文及裁剪／生命周期门槛保留。最终新测试包两版各 28 项通过，代表截图正常；旧 `readable-full` 的 28 项通过仍只作为先前候选记录。

7. FD `frame-full` 包构建成功，但 `testDebugUnitTest UP-TO-DATE` 未实际运行新的 JVM 用例；该日志单独保留并计新执行 0 项。随后 `frame-verified` 完整复核实际执行 62 项，最终只使用后者的 XML／provenance。
8. 首次真实聚合错误拒绝已实际执行的 JVM 任务：原脚本读取原始字节保留 CRLF，而行尾正则只接受 LF。仅补行尾 CR 兼容后通过，不改原始日志、不接受缓存／跳过。构建与 native 解析覆盖 LF、CRLF、重复 CR，核心自测 7 正例／19 拒绝、历史解析 3 正例／9 拒绝均通过；随后完整证据聚合成功。

Canvas 初次导入缺少必须的 icon 字段、辅助文本溢出及重复标签页编辑锁均先修正，再检查实际草图。首轮词表提取错误地假设只含字母，发现 4 个带连字符词后修正解析与核对。访客外部 files 无法经 run-as 读取且无 su，未修改设备 root 设置，后续截图改存私有 filesDir 并受限导出。所有前序日志保留，不把错误清理成通过。

## 文本证据

同名前缀的 `results.json` 保存最终方法、APK 和输入摘要，`sources.json` 保存两版冻结与差异边界；`main/fdroid-build.txt`、`main/fdroid-native.txt`、`main/fdroid-jvm.xml`、`main/fdroid-resources.json` 分别提供原日志规范化副本、完整 8 套件 XML 汇总和 180 个编译值。`visual-review.json` 与每版 `window-diagnostics.json` 只保存文字、统计与摘要，`cleanup.json` 保存限定清理回执。

`history.json` 及历史日志保存所有本批已记录失败、白屏候选和缓存／旧包排除。`evidence-manifest.json` 逐项记录提交文本摘要、来源原始摘要和转换方式；原始日志、XML 与图片仍保留在本地任务目录。JSON 使用 `<task>`、`<main-android>`、`<main-repository>`、`<fdroid>`、`<workspace>` 表示本地根路径，仅为可移植的文本证据，不是下载地址。源码冻结生成时的 runtime pending 字段保留其原时点含义，最终运行结论以独立 results 为准。
