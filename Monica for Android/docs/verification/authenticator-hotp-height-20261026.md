# 验证码 HOTP 紧凑生成按钮修复（2026-10-26）

## 原因与行为

原实现为普通验证码磁贴设置固定高度，HOTP 使用最小高度并额外显示“生成下一个”按钮。公共 API 32 模拟器的修复前回归测得两者分别为 142dp 和 154dp，复现了混排高低不齐。

所有验证码磁贴沿用原来的固定高度计算，不额外拉伸 HOTP 或其所在行。HOTP 的“生成下一个”按钮占用其他磁贴显示次码的底部位置，减少内部间距、去除按钮内容内边距；文字根据真实可用宽高自动调整，保持单行完整显示。

磁贴仍根据实际标题、验证码和字号测量原有内容，默认紧凑高度为 142dp。生成按钮在剩余底部空间布局，不再通过最小高度撑大磁贴；标签占满内部宽度，避免居中段落和文字控件宽度不一致。设备回归严格检查当前码和按钮文字无溢出，而非仅检查卡片等高。

生成按钮只推进对应 HOTP，点击卡片仍复制当前码；进入多选后禁用生成，卡片高度不变。标题与账号仍按原规则显示，列表模式和默认隐藏验证码的行为保留。

## 设计与测试环境

已重新载入本地 M3E Canvas 的 `authenticator-hotp-height-20261025` 项目并检查标准字号和放大字号的实际单页预览：六张磁贴、三排保持原有紧凑尺寸，HOTP 底部生成按钮与次码位置对应。可编辑 JSON、完整本地分享链接和截图保存在本机 `docs/design/authenticator-hotp-height-20261025/`，不纳入版本库。

复用任务开始前已运行的公共虚拟机 `Monica_Issue136_API_32`（Android 32、x86_64、emulator-5554）。测试使用固定时间和合成验证码数据；公共设备的系统字号保持 1.5，每个布局测试通过 Compose 单独指定字号。

旧遮挡测试曾继承设备的 1.5 倍字号，却断言普通字号下才显示的两个验证码。已明确指定该用例字号为 1.0，保留独立的大字号测试与原断言。最终按钮标签根据实际剩余宽高适配单行文字，避免先前放大方案中英文标签换行与圆角裁切的问题。
