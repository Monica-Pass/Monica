# 本地旧项目重复账号字段保存修复（1.0.325，未发布）

用户在 Monica 本地旧多密码项目中打开编辑页、直接保存即出现“无法读取这组账号。原有数据已保留”。最新日志来自 1.0.325-26110512-31 / API36。此前删除验证器的修复未覆盖全部旧数据形态，不能据此前测试声称原问题已经解决。

用户随后提供的单条 JSON 显示两个相同的 `monica.content.credential`，以及两个相同的 `monica.content.order`。原读取器使用 singleOrNull，即使副本完全相同也返回空，restore 将其判为不支持的 metadata，编辑器因此拒绝保存。合成模型回归已复现同一个 UNSUPPORTED_METADATA 失败。用户的明文 JSON、标题、账号、密码、实际 UUID 均未写入夹具或报告。

现在逐份解析账号字段，只有全部合法且完整 JSON 对象一致才接受，包括未知属性；JSON 空白和属性顺序可以不同。正常保存后收敛到一份，保留较严格的保护位、原账号/密码 UUID、未知字段以及同名普通自定义字段。损坏、未知版本和内容冲突仍阻止保存。完全相同的顺序字段同步收敛，保留其中指向其他账号的 token，不推断它是孤立内容。

独立的旧 OTP 兼容仅用于编辑器：本地同一显式账号、每条都有合法 metadata，用户名与账号备注一致，OTP 仅有空值和唯一非空值时，允许编辑。普通保存和修改密码保持各行原 OTP；主动修改/清空 OTP 时应用到整组。不同非空 OTP、缺失 metadata 或外部来源仍拒绝；其他 restore 调用保留原严格约束。兼容不做批量迁移，不以用户名或标题合并账号。

编辑器将账号解密/恢复放到后台，取消继续抛出。加载失败增加限流且不含值的类别/代码位置日志，不写标题、ID、账号、密码、OTP 或异常 message。未改变算法、KDF、数据库 schema 或备份格式。

可疑来源审阅：当前不使用 destination writer 的备份恢复分支可能把已存在项目映射到旧 ID 后继续追加自定义字段，这是副本的一种可能来源，但 JSON 没有历史操作记录，本轮不能认定用户实际走过此路径。未扩大到通用导入去重。
