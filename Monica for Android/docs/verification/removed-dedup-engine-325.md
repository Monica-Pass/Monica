# Dedup engine removal — 1.0.325 (ordinary Android)

The entire explicit dedup engine is removed: settings/search entry, single-vault analysis/cleanup/recovery UI, cross-vault merge, ViewModels, services, adapter-only methods and exclusive resources/tests. This is an unreleased code change; no tag, release or APK delivery is performed.

## Compatibility and preserved behavior

- Room stays at schema 85. The inert encrypted recovery table has the exact old schema identity `f1cc89b0bd71d086b7a81d230b3fe1b7`, with no runtime engine DAO. Existing rows and recovery files are not deleted.
- The retired route redirects to Sync/Backup and removes itself from the back stack. Two inert enum types retain their old binary names/constants solely so Android can deserialize old saved UI state before discarding the route; no engine behavior remains.
- Exact release-only keep rules preserve those two enum types through shrinking. R8 9.1.29 was run on their actual compiled Kotlin classes: without the rules both disappear and legacy deserialization fails; with the rules both old serialized fixtures deserialize successfully. The initial standalone harness lacked JetBrains annotations; adding the actual library fixed the harness, with its failed log retained. This is a focused classfile comparison, not a complete release APK validation. Adding the release-only rules did not alter the Debug source inputs.
- Timeline source labels retain their previous translations under a timeline-specific resource name. Other resource values were compared across 48 affected XML paths.
- List display deduplication, import/restore merging and sync coalescing remain. All 155 protected KeePass/list source paths are byte-identical to task entry. Existing uncommitted list changes remain local and are excluded from this commit.
- Current Chinese/English release notes replace the engine addition claims with an explicit removal notice. Historical releases are unchanged.

Binary inspection confirms no engine classes/adapter methods or compiled engine resources, with native x86_64 libraries and the inert table retained. Its APK hash changed, so all 65 device methods were rerun with main05. This is not claimed to be the same APK as main04. F-Droid's static version metadata keeps its production APK identical to fd02.
- Related JVM suite (main03): 670 methods, 661 passed and 9 failed. The same 9 source-text guard failures occur against reconstructed exact pre-removal sources and current sources using identical compiled tests (94 methods in each comparison). Kotpass's 7 methods passed in an earlier executed run; up-to-date tasks are not counted as fresh executions. Ordinary main04 adds only inert enum types and their device serialization test after main03. Final main05/fd03 change only the settings-search device assertion. Main05 gets the full device selection due to the date-metadata repackage; F-Droid reruns the settings group while retaining its unchanged APK's storage results.
- Final MuMu API35/x86_64 device selection: 65 distinct methods, 64 with passing results. ## Backup and test environment

The pre-removal implementation is backed up at `d8b5170445d35978878cdbbf2c9d73bbc78339d0` on `codex/dedup-engine-backup-20261106`; remote SHA and 76 source/test file contents were verified. The removal commit is a separate reviewed change.

The shared API32 AVD could not allocate an isolated user; existing users/configuration/disks were preserved and the task-started instance was stopped. Testing used existing MuMu clone 1 with only the task-owned synthetic user 13. After restart Android identifies it as a managed profile of user 0 and refuses a direct user switch; instrumentation/install/run-as still target user 13 and execute under u13 application UIDs, with profile activities displayed on the parent desktop. That profile and the task-owned ADB server are removed/stopped after testing; original MuMu users 0/10/11/12 and all virtual disks/configuration are retained. Screenshots are actual Compose component captures in the instrumented Activity, reviewed at normal and 1.5 font scale, and remain local ignored files only.

An explicitly user-requested read-only subagent independently reviewed source scope, all preserved affected resource entries, APKs, compatibility and the known failures.
