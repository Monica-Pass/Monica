# 1.0.327 本地主密码与可移植备份 KDF 升级

状态：主任务选定的最终构建与设备批次已通过，实际限制及历次失败见下文。

本报告由本地任务生成器从已完成的构建回执、JVM XML 和逐方法 instrumentation 状态生成；日志仍在写入且没有完成回执的运行不计入。详细数据见 [结果 JSON](password-kdf-upgrade-327-results.json)。

## 范围与独立协议

本次维护普通版与 canonical F-Droid 的未发布 1.0.327。本地主密码保护、可移植 ZIP 备份、Bitwarden 账号 KDF、KeePass KDBX 与原生 MDBX 是独立协议；本次应用级选择不修改第三方库格式或账号参数。

| 路径 | 原格式读取 | 新写入与选择 |
| --- | --- | --- |
| 本地主密码 verifier 与 MDK 密码封装 | 缺少元数据时按历史 PBKDF2-SHA256 100000 读取 | 默认 PBKDF2-SHA256 600000；可经当前密码确认改用 Argon2id |
| 本地独立恢复材料 | 保留 V1 的 PBKDF2-SHA256 600000 外层及历史 100000 内层读取 | V2 外层跟随当前应用 KDF，指纹包含应用 KDF 元数据 |
| 可移植加密 ZIP | 保留 `MONICA_ENC_V1` | 默认兼容 V1／100000；增强 V2／600000 另行选择 |
| 既有配置字符串 | 保留无版本 PBKDF2-SHA256 100000 读写 | 本次不原地改变该无版本协议 |

Argon2id 固定参数为版本 0x13、64 MiB 内存、3 次迭代、并行度 1。只接受列举的参数编码，未知版本、未知算法、缺损或错误类型的元数据拒绝处理，不尝试降级为旧 KDF。

## 旧用户升级与回退边界

历史无元数据用户在首次成功输入原主密码时，先按 100000 次验证并解开原 MDK，再准备 600000 次 verifier、密码封装与元数据。数据加密使用原 MDK；不因升级重建 MDK，不批量重加密项目密文。生物识别不能提供主密码，因而不能独自完成此迁移；最终是否有其他更新入口要求重新输入密码，以实际入口验证为准。

一次受锁保护的凭据更新协调完整 verifier、盐、MDK 密码封装、KDF 元数据及恢复材料；恢复文件与偏好镜像仍分步提交，具体中断边界见下文，不是跨文件原子事务。旧包装损坏时，即使进程存在暖 MDK 缓存，正常密码迁移及切换 KDF 仍不得绕过真实密码解包。密码重设使用单次认证、原凭据快照和运行时代际；已有设备／安全问题授权重设保留独立入口。

升级后的本地凭据不能被固定 100000 次、忽略新元数据的旧 APK 正常解锁。本次不保存旧的 100000 次 verifier 或密码包装作为兼容后门。因此“允许同签名覆盖安装旧 APK”不代表“升级后的本地数据支持旧 APK 解锁”。如需旧端交换，使用明确选择的兼容备份；不得把降级安装或恢复旧备份描述为无损回退。

## 恢复、原子提交与取消

恢复文件 V1 继续使用原四字段指纹及原 AAD。V2 使用五字段指纹，将应用 KDF 元数据计入；MDK 密码封装 AAD 绑定该参数编码，恢复 key 与 snapshot 的 AAD 也绑定对应版本信息。选择 Argon2id 时，当前独立恢复文件的外层同时使用 Argon2id，避免保留一个 PBKDF2 外层作为当前本地密码猜测验证通道。

上述保证仅覆盖当前本地活跃材料。用户保留的历史备份、独立导出文件、旧设备或另行使用相同密码的系统具有各自的成本；本次不会重写这些副本，不能宣称所有历史密码验证通道均已消失。

提交沿用“先写已核验的独立恢复文件，再提交加密偏好镜像”的顺序。两者不是一个文件系统事务。恢复文件提交前失败时原凭据保持可用；恢复文件已提交而镜像未持久化时，正常入口拒绝继续使用旧镜像，保留新恢复文件供确认恢复。不得将此称为完全回滚。

派生、序列化和加密读回核验在后台完成；最终提交前再次执行取消／锁定／凭据冲突检查。一旦提交开始，允许完成一致的材料写入，取消或锁定仍不得发布迟到 MDK 或认证权限。运行时凭据 epoch 用于撤销同进程其他旧认证请求。

Android `SharedPreferences.commit()` 返回失败时，内存映射可能已经更新。本次显式标记待完成镜像，拒绝该进程继续使用“内存已新、磁盘仍旧”的状态；只有在写锁内刷新真实磁盘密文，并核验其与当前恢复材料一致后才解除阻断。确认恢复使用独立新存储及原子 selector 切换，保留原材料。

## 多进程边界

恢复材料及 selector 的读改写使用可重入的进程内锁与操作系统文件锁。每次恢复快照／受保护设置写入都有同步 revision；陈旧 `:ime` 进程不能凭相同凭据 generation 覆盖另一进程刚写入的设置。

准备好的句柄从恢复文件最多 4 KiB 的头部核对 generation，保留 selector 与 keyset 校验，不等待慢恢复线程持有的大锁。generation 是认证撤销边界；普通设置的 revision 是写入冲突边界，不强迫重新认证。同进程最终 canonical／mirror 写入窗口使用精确绑定旧／新修订的在途标记，避免自身并发读取误判为外部凭据换代；该豁免不跨进程，不覆盖昂贵 KDF 阶段。

外进程观察到凭据换代时会撤销旧缓存与会话，重新认证可能是预期行为；不能崩溃、误认为“尚未设置密码”、继续填写旧凭据缓存，或要求用户清应用数据。重新准备时，在写锁内读取原始加密 XML 并刷新进程缓存，不能依赖 `MODE_MULTI_PROCESS` 的时间戳启发式。

同 generation 下的设置修订过期可以在写锁内刷新后合并明确的改动。保留会话需要原 keyset 相同、当前恢复 snapshot 认证成功、缓存与 canonical 的凭据指纹及 generation 一致；刷新后再次核对真实镜像 generation／revision 和完整凭据。未满足条件则锁定并拒绝。新入口发现仅 revision 过期时请求重新准备，不把一次普通设置保存变成输入法重新登录。普通设置读取的全局即时一致性仍不在本次承诺范围内。

静态复审发现输入法部分访问检查在异常捕获之外。当前补丁已将输入法访问检查转入既有锁定路径，将自动保存的密码状态读取移到受保护 Activity 入口，将 Passkey 异步检查失败转入受控阻断页，并让主界面访问策略返回已配置但不可进入的状态。主界面重新准备联动与多进程验证的实际范围见下文；底层 fail-closed 不能单独证明完整页面体验已验收。

## 备份兼容

兼容备份 V1 的魔数、固定 100000 次 PBKDF2、盐／nonce／密文布局保持不变。经典 Windows 与 KMP 中已有固定 V1 读取器不能读取增强 V2，不能把它们的本地登录 KDF 与备份协议混为一谈。

增强备份 V2 使用独立魔数及明确参数头，完整参数头纳入认证；读取器识别错误版本、错误参数或错误密码后直接失败，不重新按 V1 或明文 ZIP 解释。准确格式与测试向量另见 [可移植备份协议](../storage/PORTABLE-BACKUP-ENCRYPTION-V2.md)。现代独立 Avalonia 当前检查到的 WebDAV 备份是自身 JSON 协议；不能据其具备 Argon2 本地能力宣称已支持 Android ZIP。

## 二次验证与本轮最后修正

高成本派生不能继续留在界面线程。本轮最终收尾将 Passkey、普通版凭据导出、Steam、笔记、钱包、密码详情、删除／导出及设置等既有密码确认入口接入有界后台验证；原授权策略和后续业务操作保留。公共组件在取消、暂停／停止、卸载、锁代变化或目标替换后撤销请求，最终成功还检查前台、屏幕状态、原目标及 staged attempt 提交。显式跳过密码的既有策略不因异常而自动启用。

最终审计另修正 `ChangePasswordScreen`：只有真实凭据提交成功后才显示成功并执行后续回调，失败、取消或未确认结果不能提前报成功。密码存在性检查将“hash 缺失但仍有 MDK／KDF 等受保护材料”的损坏状态视为已有保护，拒绝进入新建密码覆盖路径；这不是认为缺失凭据仍可认证。上述修正和新增 shared secondary 密码确认回归须以本轮最终重建及设备回执验收。

上述新增入口及测试发生在早期核心／UI 批次之后，因此早期通过不能替代最后重建。现有生物认证与硬件密钥分支具有独立策略；不能把密码组件的测试概括为所有生物认证、所有 credential-provider 或完整系统 UI 流程通过。

## 失败及修正记录

- `main-build-01` 的生产编译／部分产物完成，但新增测试含三处 `emptyMap` 类型推断及五处 `performImeAction` 使用错误，联合命令失败。补类型与正确调用后复测，原日志保留。
- `main-build-02` 出现四个源码 guard 失败；其中两处跟随本轮认证函数拆分，另两处断言已过时于此前银行／自动填充代码。复审按真实路径更新，保留原安全后置条件。独立 guard 首次 15/16，修正已有 OTP 委托断言后两版各 16/16；这些宿主结果不替代 Gradle。
- `main-build-03` 联合命令非零，已生成的 APK 可作为明确记录的中间产物；后续 `main-tests-04` 通过不能改写先前命令结果。
- `fd-build-01` 的主／测试包生成，但 JVM 一项 Argon2id 64 MiB profile 在默认 512 MiB worker 已占用堆下触发安全可用内存门限。任务级 worker 调整为 1 GiB，生产安全门限未放宽；最终重跑结果按上表为准。
- `final-main-ui` 漏传三个测试类的 `.screens` 包段，出现三个 initialization error，另三个 gate 方法通过。修正调用类名后的 `final-main-ui-02` 使用同一 APK；不能称初次整批通过。
- `main-regression-01` 的两个旧夹具分别依赖旧 `getString` 读钩子，以及预期陈旧／不可读句柄的 `isMasterPasswordSet()` 抛异常。前者改在实际 snapshot-map 解包点注入锁定；后者改为断言该查询返回 `true`（仍受密码保护），实际敏感读取仍抛异常并撤销会话。原数据字节和配置保留要求未删除。最终复测按所选批次计。

- `main-build-05` 对应的 `final-main-ui-03` 为 29/34：26 项既有 UI 和 3 项新增 secondary 用例通过，另 5 项在等待 staged-attempt 延迟钩子时超时。原夹具通过反射替换 manager 的 preferences 包装，遮蔽 enrollment 所需的 mirrored-preferences 类型；该结构缺陷由源码确认，原运行未输出异常栈，具体抛出位置未独立证实。修正仅把钩子移到 fixture context 的 backing `SharedPreferences.getAll()`，保留真实加密／镜像包装链，且仅在 `PasswordVerificationAttempt.stage` 的调用栈内触发；没有增加超时或删除断言。该失败批次不能算作取消／迟到结果保护通过。
- `final-main-ui-04` 已到达所有延迟钩子，仍为 33/34（runner 43.233 秒）：disposal 用例改变 Compose 可见状态后立即 release，尚未等待实际重组和 `onDispose`，因而观察到一次成功。测试修正为先 `waitForIdle`、断言确认／取消节点均已移除、成功数为零且 runtime MDK 不可用，再释放 worker；保留全部后续拒绝和原数据可读断言。未改生产门控，未用固定 sleep 或放宽超时替代真正卸载。

## 测试实际覆盖与边界

本地 KDF 独立向量为 30 组，包括 100000／600000／Argon2id、16／32 字节盐、Unicode、空格、组合字符、NUL 和超过 HMAC block 的长密码；最初 24 组保持不变，新增六组 Python 与 OpenJDK 17 对照一致。另有畸形 UTF-16 与平台 JCE 历史行为对照。备份 V1/V2 的 10 组独立 Python/OpenJDK 向量一致；设备/provider 运行状态单列，不由宿主结果推定。

本地迁移用真实 SecurityManager 与隔离加密偏好验证旧 100000 次凭据、保留同一 MDK 和项目密文、错误密码／损坏包装、KDF 双向切换、密码重设、锁定／取消／迟到结果及恢复材料。部分故障用可控夹具注入，不等于真实断电。warm-cache 损坏包装用例可能在恢复指纹处提前拒绝；独立 JVM 包装测试另覆盖实际 unwrap 拒绝。

两版实际执行旧 APK 种子→覆盖安装→新密码重入及后续 instrumentation 进程读取。该 checkpoint 使用 `ContextWrapper` 隔离配置、手写 SQLite `secrets` 表、合成加密附件和受保护 passkey 字符串，并核对数据库／附件字节与旧材料；它不是完整生产 Room 数据库、完整主应用 UI、真实 Passkey 注册／使用或用户密码库升级验收。已有“fresh manager/cold cache”用例仅同进程冷缓存；独立 instrumentation 重启与真实 `:ime` PID 用例单独记录。

跨进程用 Debug-only、同 UID、未导出的合成服务运行于真正独立的 `:ime` PID，核对旧句柄拒绝／新句柄成功及两个写者仅一方提交、未知受保护值和原密文保留。测试路径映射限定独立 UUID fixture，不能描述为完整键盘 UI、系统自动填充或真实用户库操作。

设置／重设 UI 的控制型操作用于隔离取消与状态机；managed login 和 secondary confirmation 用真实隔离 SecurityManager。generation gate 的旧缓存夹具在同进程冻结句柄，真实多进程证据独立。备份设备用例覆盖 codec、拒绝时目标保留、无版本配置字符串及手动／共用云 ZIP 创建；没有连接真实 WebDAV／OneDrive 账号。
