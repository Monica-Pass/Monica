# 1.0.332 文件夹备份、MDBX 状态与生成器语言验证

普通版与 F-Droid 的「同步与备份 → 文件夹备份」使用独立密码和现有加密 ZIP。通过系统选择器授权目录后可手动备份，或开启每 12 小时的定期检查及改动后备份。改动后等待 2 分钟，两次备份至少间隔 15 分钟。执行时需要已解锁的前台会话；这不是锁屏定时写入的承诺。

写入新文件后按长度与 SHA-256 读回验证；仅轮换本次安装、同一目录和密码对应的已验证自动备份。手动文件永久保留。非本机提供器另保留 48 小时内的文件及至少两份更早的备份。设备读回成功不能证明网盘已完成上传。MDBX 的同步状态与错误均取自当前数据库记录；安全写锁仍由提供器支持。生成器五档强度文字随语言切换。

在 Release 应用中从真实设置开启自动备份，系统自行调度产生自动文件；手动备份另有永久标识。设备测试另用 WorkManager 实际运行自动备份 worker，验证锁定时无写入及解锁后的完整自动归档；另有撤权、读取/写入故障、不完整目录、不可读生成历史、拒绝删除、保留外来文件、MDBX 真实提供器写锁与过期诊断显示、大字号阿拉伯语及 22 种语言的强度标签检查。每版 22 个语言配置各有 24 条文件夹备份字符串。两版保留了各自的导入导航。生成器五档强度在 19 套资源中直接翻译，3 个中文地区配置沿用通用中文。阿拉伯语、法语、印尼语、意大利语和土耳其语中把 Fair 误译为“公平”或“展会”的中档已更正，并在两版最终 Debug/Release 的资源表中逐项读取核对。

升级顺序：普通版 331 → 首批 332 混淆包完成覆盖和真实备份恢复，再覆盖安装修正上述五条文案的最终 332。普通版最终 Debug 的 DEX、原生库与清单字节不变，Release 三个 DEX 的字节不同；没有据此假定等价，而是在最终 Release 新增记录，经过正常间隔再次自动/手动备份、删除合成条目、导入并冷启动读取。F-Droid 从 331 直接覆盖最终 332 后完成同一套验收。普通版最终 Release 还验证新真实编辑触发的文件名与手动备份不同，并在 15 分钟最短间隔后生成。普通版从手动档恢复，F-Droid 从自动档恢复：均先确认删除合成记录，导入后在新 PID 核对密码。F-Droid 最终 Release 的 13 个 DEX／原生库／Manifest 条目与修词前逐字节一致。两版所有条目的比较见验证数据。

早期普通版设备批次为 1/4、14/15，F-Droid 为 13/15；这些失败保留在任务原始日志中。修正了测试宿主、Room 通知计数夹具和备份完整性验证。普通版 main06、旧版 F-Droid old-fd01 的磁盘写满及早期编译失败均不计为通过。旧普通版 Release 的测试框架在 R8 裁剪后无法链接，在执行用例前中止；实际 Release 覆盖与恢复改用 ADB 操作应用及系统界面，未放宽生产 R8。验证仅使用专用包名、测试签名和合成数据；未验证真实 RSAF 账号/云端上传、物理设备、掉电或完整 12 小时调度周期。安装包校验、设备用时、身份连续性和恢复阶段见[验证数据](folder-backup-332-result.json)。
