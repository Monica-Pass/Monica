# 强密码建议后未保存条目：源码排查（2026-10-31）

## 反馈范围

用户提供了另一条反馈：“最近在几个网站注册账号发现能弹出强密码建议，但是注册完之后没有记住密码。”具体网站、浏览器、系统、Monica 版本，以及是否实际接受建议、是否出现系统保存提示均未知。不得沿用前一位用户的 HyperOS 1/322 信息，不认定两条反馈同因。

本轮只有源码核对，未针对这条反馈运行模拟器或实际网站复现，没有生产修复或新构建。以下说明的是现有分支及排查方向，不能当成该用户根因已确认。

## 已确认的实现

1. `FillResponseBuilderNg` 仅向识别出的 NEW_PASSWORD 字段提供强密码建议，建议是否出现与保存是否启用是独立条件。它随后调用 `AutofillSaveInfoPolicy` 配置系统保存。
2. `PasswordSuggestionActivity.acceptSuggestion()` 在返回密码 Dataset 之前，先通过 `PasswordHistoryManager.addHistory()` 写入生成历史，记录密码、时间和已捕获的来源/账号。这一步使用现有加密存储，不创建 PasswordEntry。历史写入发生异常时不会继续成功返回该 Dataset。
3. `PasswordSuggestionActivity.kt` 和 `FillResponseBuilderNg.kt` 相对普通版 `V1.0.322` 无差异。生成历史上限为 50 条，可在生成器右上角“历史”入口查看；筛选项包含 AUTOFILL（自动填充），默认可见。找不到时先检查筛选和是否已清理历史。只有用户确实接受了这一强密码建议入口，才有该历史写入保证；其他生成器/手动复制路径不能一概套用。
4. `AutofillSaveInfoPolicy.build()` 在关闭保存提示或处于系统兼容模式时返回 null，而强密码建议本身仍可能显示。兼容模式目前跳过保存是为避免保存掩码值，不能仅凭这条未知网站反馈移除该限制。
5. Android 13 AOSP `Session.showSaveLocked()` 要求至少一个可保存字段相对自动填充值/初始值发生变化，并排除匹配已有 Dataset 的情况；没有 SaveInfo、必填值空或没有变化时不会请求保存。新生成的密码也通过 Dataset 返回，不能把“生成并填入”直接等同于“网站提交后必定弹出保存提示”。特别需要复现账号和密码均由数据集填入、账号由页面预填、以及浏览器兼容模式的情况。

生成历史是密码找回入口，不等于已经保存为可供下次登录匹配的完整密码条目，也不证明网站注册成功。不能在缺少实际表单/回调证据时将未完成注册静默变成正式密码条目。

## 下一步取证

- 若用户确实点了“使用/接受强密码”，先到“密码生成器 → 右上角历史”按注册时间/来源检查，必要时开启自动填充历史筛选；找到密码后可手动保存完整账号条目。
- 复现时区分“根本没有系统保存提示”“点击系统保存后不打开 Monica”“已进入编辑页但没有成功写入”三个阶段。仅“没有记住”不能定位到某一步。
- 现有日志中的 `compatMode`、强密码接受及历史写入结果、保存取值跳过原因可缩小范围；必要时结合系统 Autofill 日志查看 `NO_SAVE_UI_REASON_NO_SAVE_INFO`、`NO_VALUE_CHANGED` 或 `DATASET_MATCH` 等原因。应用日志未出现保存行不自动等于系统未回调，322 的阶段日志并不完整。
- 没有新增中转 sheet，没有改变 PendingIntent、安全验证、加密格式或用户数据。本轮未提交、推送、发布或交付 APK。
