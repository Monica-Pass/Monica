## Protocol and safety boundaries

Optional capabilities extend the existing v2 hello. Only paired peers with matching nonempty pair IDs and expected-device checks can negotiate incremental records or encrypted resume. Initial pairing and unsupported capabilities retain the existing full protocol. Receive-only currently lacks an outgoing snapshot/content key and therefore uses full record transfer.

Inventories are exchanged inside a fresh Noise session, never discovery broadcasts. They contain exact serialized record SHA-256 versions, aliases and attachment IDs whose AEAD chunks and complete plaintext digest were checked. Changes, deletion records and alias changes are sent; identical omitted records remain in the receiving replica. Missing attachments are selected independently of record differences, including pending records. No remote checkpoint is persisted or treated as physical application success. The existing pending application, deletion preview/revision/review/omit policy, conflict retention, sync direction and Passkey policies remain mandatory.

Delta artifacts use the existing source snapshot content key and existing encrypted formats. A cancellable publication gate prevents concurrent peers bypassing the eight-copy/512 MiB per-source quota. Quota exhaustion alone uses the original encrypted full snapshot; corrupt or symlinked cache errors still reject the transfer. Immutable encrypted cache copies are bounded to eight and 512 MiB per source; new plaintext record copies use RAII wiping. Record state and inventory are limited to 64 MiB, with bounded counts/identifiers. Full local export and inventory validation remain necessary; reduced network bytes do not prove faster preparation or constant-memory record processing.

Resume is bound to expected peer, pair, handshake-secret digest, artifact name/size/full ciphertext digest. Every reconnection performs a new Noise handshake. The sender checks the proposed prefix and unchanged source; the receiver checks the entire ciphertext and publishes a new destination only after flush/verification. Applied receipts still require the existing application path. Resume saves only ciphertext and opaque local metadata, never vault plaintext, keys or Noise state. Limits: eight partial artifacts, 512 MiB, 600-second eligibility, exclusive active leases and symlink rejection. Prune runs every minute in a live coordinator; lock/background/cancel and forgetting a device clear inactive state, with sticky discard permission and an independent retirement coroutine performing a second clear after cancelled workers retire, even without foreground ticks. Process death does not promise immediate or exact ten-minute physical deletion of orphaned ciphertext.

Coordinator cache roots additionally use process-held owner leases and a short cross-process creation/retirement gate. Startup acquisition reclaims only orphaned strict UUID roots in `cacheDir/device-sync` whose entire bounded layout is recognized as protocol artifacts. Active roots remain leased until process exit; unknown layouts are preserved, and root/owner/gate anomalies reject acquisition. Filesystem work runs on IO. Symlinks are rejected without following them, and owner hard-link aliases are rejected before opening a second descriptor that could invalidate a POSIX lock. This does not visit `filesDir/device-sync`, databases or persistent attachments. Root enumeration and each layout are capped at 4,096 entries. Orphans may persist until a later successful acquisition; there is no guarantee of immediate physical erasure after process death.

Binary attachments use bounded 512 KiB Kotlin/JNI chunks and encrypted streaming storage. ID, index, size, EOF and final SHA are checked; the final chunk is not released before validation, and storage failure removes its temporary encrypted write. Image/icon and some native repository adapters still use bounded complete arrays; this is not end-to-end constant-memory processing.

## Hotspot and scheduling

User-requested LocalOnlyHotspot (API26+) owns only its reservation. QR envelopes contain expiring Wi-Fi credentials and an existing 256-bit invitation, never the master password. WifiNetworkSpecifier (API29+) retains the system confirmation. Network callbacks provide coalesced hints; they do not bind the process or bypass existing per-socket Wi-Fi/VPN routing. Foreground active transfers poll at 500 ms; idle work has network/action/presence wakeups and a five-second fallback.

Lock/background/cancel/expiry clear invitations and owned connections. Standard floating system confirmation pauses the app without stopping it; full-screen OEM flows that stop it remain cancelled, with a fixed retry/manual-connect prompt. No background exemption was introduced. Generation checks reject late callbacks and resetting scan state permits retry. Existing user-owned hotspots are retained.

## Remaining practical limits

Native TCP tests and fake Android connectivity drivers do not constitute physical wireless acceptance. Only Debug application/test artifacts were built in this task; no new minified Release/R8 validation was performed. Discovery presence remains an untrusted hint followed by authenticated transfer; this task does not add authenticated discovery announcements. Historical release notes and version codes remain unchanged; 1.0.324 remains unreleased.
