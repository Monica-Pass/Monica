# Send 搜索、账号选择与草稿入口 — 1.0.327

记录日期：2026-11-10。适用普通版与 canonical F-Droid 的未发布 1.0.327，两版均在本地 main。两版 Debug 主包、测试包和各 44 项选定 JVM 测试通过；普通最终设备整批 33/33，F-Droid 整批 31/33，两个失败方法使用同一安装包独立复测 2/2。F-Droid 不能称首次整批全绿，接收器测试的批次稳定性问题仍保留。

## 行为与设计范围

Send 列表移除常驻的“打开链接”和“草稿”全宽按钮。现有搜索框保留内容搜索，并在输入完整合法 Send 链接时显示带目标域名的打开操作；输入和识别本身不发起网络请求，点击才进入原生接收流程。未连接 Bitwarden 账号或账号全部锁定时，只要 Monica 会话已解锁，仍可接收链接。自托管服务继续要求用户确认目标后再联网。

新建页用单张账号卡片显示当前账号和服务器，点击打开 Bitwarden 账号单选底部面板。草稿入口位于新建页顶栏，通过底部面板查看和恢复本地草稿。窄屏导航与宽屏内嵌编辑器使用同一宿主。设计保留原有表单分组，以卡片与底部面板减少常驻控件；草图仅用于布局说明，不作为原生交互、字号适配或安全验证证据。

恢复草稿前，当前表单有修改时需确认替换，取消保留当前输入。每次恢复都会重建该次编辑状态，包括再次打开同一草稿，避免复用前次正文、密码或类型。正在编辑的草稿不能在面板中删除，包括本页首次保存形成的草稿；其他草稿仍沿用明确的本地删除确认。

## 保留的安全边界

- 链接识别复用原有严格解析器，临时解析对象立即关闭；操作卡片仅显示域名。含密钥片段的链接不进入可保存的界面状态或导航参数，交接后清空搜索和待打开状态；接收器通过更新状态读取初始链接，避免一次性 effect 继续持有首次完整链接。锁代变化或离开前台时撤销相关界面及内存状态。
- 账号选择只改变当前新建表单的目标，不切换全局活跃账号。已有 Send 和已保存草稿继续绑定原账号完整身份与服务端配置；失去授权或身份变化时撤销编辑，不迁移至其他账号。
- 提交结果不确定的草稿保持只读，核对操作使用原草稿和原提交记录，不重新保存或生成新的创建请求。草稿加密、文件载荷和服务层核验沿用原实现。
- 宿主统一退出清理，避免锁定与编辑器退出重复触发导航或提交取消。合法文件选择器继续沿用原有前后台例外和锁代检查；接收器的目标确认、文件输出授权与迟到结果拒绝逻辑保留。

本次范围是 Send 入口、表单宿主、账号面板及相应测试和文案；没有更改密码库加密算法、KDF、草稿存储格式或 Send 协议。上述为实现与静态审查结论，运行时覆盖以最终设备回执为准。
