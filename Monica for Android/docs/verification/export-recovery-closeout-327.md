# 327 导出与密保恢复收尾验收

2026-11-13 完成。普通版与 canonical F-Droid 均保持未发布 1.0.327，versionCode 分别为 12 / 34。源代码、构建、回归、实际 R8 覆盖升级、加密备份恢复及环境清理已经闭环。没有提交、推送、标签、发布或 APK 交付。

本次接管没有再次修改生产代码、构建或运行设备测试；复核并沿用原会话的最终产物及原始回执，修正任务本地核对脚本，完成离线检查、文档和设备清理。保留其他任务的已有修改。

## 完成的行为

| 问题 | 最终行为与边界 |
| --- | --- |
| 密保设置离页、取消或暂停后迟到保存 | 页面撤销传入实际 worker 与最终设置授权检查；撤销先于最终授权时拒绝保存，不发布旧页面结果。已经授权提交的写入不承诺回滚。 |
| 暂停后重新进入沿用旧操作 | Back、pause、stop、替换与销毁撤销旧页面状态；新页面重新建立操作状态。阻塞中的底层工作仍在退出时释放原许可。 |
| 恢复冷却结束后页面不刷新 | 通过有界 worker 重新查询持久限速状态并刷新；查询失败仍保持阻止。查询耗时另计，不承诺严格一秒响应。 |
| 系统文件选择器返回 flags 但没有实际 URI 写权限 | 页面检查真实进程权限，拒绝缺权目标并允许重选，拒绝时不启动写入服务。ZIP / Steam 需要读写权限以便校验；其他格式需要写权限。 |
| 导出服务失去 Activity 的临时 URI 权限 | 仅把确实获得且已验证的 READ/WRITE 权限随同一个 URI 和 ClipData 传入服务。选择器请求 READ/WRITE/PERSISTABLE 能力，但没有调用 `takePersistableUriPermission` 持久化授权；服务仅转发 READ/WRITE，没有广泛、前缀或自授予权限。 |
| 大型恢复协程在取消／CRC 异常路径崩溃及临时明文残留 | 等价拆分四个配置 DAO 分支、外层解析器和逐条目解码；每次调用独立持有临时工作区，失败／取消清理，完整成功后交接。先前 DAO、配置或文件副作用仍不承诺整体事务回滚。 |

保留恢复 challenge、认证、generation、绑定、限速及锁定检查；没有改变算法、KDF、密保答案哈希、恢复 envelope 或数据库格式。

MuMu 的 Downloads provider 仍可能拒绝实际写权限。默认主存储 Download 路径已实际成功；这不等于修复了所有系统文件提供器。

## 保留的失败及限制

- 42 份构建／instrumentation 回执的哈希、成功与失败状态均列入结果 JSON；原始日志继续保留本地。早期 class 名错误、语言混用、通知前提、测试编译与清理错误没有改写为成功。
- FD03 三个 cold-first 生命周期等待超时仍未单独查明根因。FD06 改为 core-before-lifecycle 顺序后通过原方法及原 5 秒断言，不声称解决了全部冷 provider 时序。
- 普通多个旧恢复包在取消／CRC 路径出现 ART SIGABRT；final05 的 CRC 崩溃仍保留，不能与 final06 通过合并成一次成功。
- 普通首次新备注保存驱动误以为页面已返回列表，后续冷进程确认备注；原失败保留。首次经 FUSE 拉取备份得到 103 字节错误文本，已排除，实际验收文件由原始 media 路径与远端 SHA 核对。
- 首次完整恢复比较未处理账号 ID 重映射及两个空默认值而失败；仅做上述窄化归一，并补反向检查。
- 原最终脚本把空目标库当作必须有旧账号的源库而失败；新增显式空库模式且要求全部声明内容表为空，默认源库检查未放宽。
- 另一个手写内存 WAL 审阅脚本在长度断言处失败，未运行到语义比较，不计通过。最终用标准 SQLite 读取归档 WAL，并对两版补实际内容及反向核对。
- 本次反向检查第一版误把自定义字段的绑定改成原 ID，属于无操作夹具；改为不同于该字段原 ID 的另一账号后通过。没有删掉比较断言。
- FLAG_SECURE 导致截图为黑色，不能作为最终原生视觉验收；功能验证来自实际 UI 层级、操作和独立存储证据。

范围仅为 MuMu API35/x86_64 合成数据、相关 Debug instrumentation 与单列的实际 R8 流程。没有用户真实库、物理设备、OEM、Android16、真实云账号、全部备份格式或全部凭据类型验证；本轮 R8 合成库无附件，不把其他 Debug 附件回归泛化为该 R8 库的附件验收。
