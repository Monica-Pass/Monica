# MDBX 普通编辑原生接入与历史机制核验（1.0.328，未发布）

普通版与 canonical F-Droid 的普通密码新建、编辑、账号组及自定义字段保存，已通过原生 MDBX 提交；Room 仅在原生成功后更新为投影。此次不改变加密算法、KDF 或 MDBX-2 文件格式，也不代表所有类型及所有旧写入入口已全面重构。

## 实现与审查发现

- 编辑从原生对象加载，并保存对象、Collection、vault、来源及全部分支 head 的基线。保存时，Rust 在与写入相同的 IMMEDIATE 事务中核验分支 frontier，沿用 OperationCoordinator 维护对象版本、父提交、历史、分支和同步增量。其他提交出现后，旧表单必须重读。
- 同一数据库中的账号组在一次原生事务中保存；移除账号使用 tombstone。新项目使用原生 UUID，移动及编辑保留已有身份。没有实际改动时不增加提交。不同数据库之间不承诺原子回滚。
- 仅修改编辑器拥有且发生变化的 payload 字段；保留未知嵌套字段、精确大整数、原生附件及自定义字段 UUID/保护信息。未知原生类型和不支持的 schema 拒绝普通编辑。UI 未呈现的投影 metadata 保留；改变笔记绑定前核验原生目标。
- 审查修复原生提交后回读失败的问题：已提交的对象身份在回读前记录，重试只恢复投影，避免重复创建；即使回读或取消发生在提交后，执行器仍检测实际提交并完成待发布状态处理，不以 Room 数据反向覆盖原生提交。
- 审查修复重导入时旧兼容规范化改写真实 UUID 的问题。原生库存确认的身份保持稳定，删除/类型变化沿原生状态更新；登录项目所属目录采用原生 Collection，不依赖过时 payload 提示。旧 `password:*` 兼容身份仍保留。
- 锁定、后台和离开编辑页撤销编辑会话并释放基线内容；状态发布与撤销共用同步锁，防止已撤销后迟到回读重新缓存明文。迟到结果不发布。已经进入同步原生调用的提交不承诺由协程取消回滚，实际提交仍须保留并进入同步状态处理。

所有最终构建均记录构建前后输入哈希不变。两版最终 Debug、测试与 Release 的源码/绑定/provenance 输入均与最终实现对应；早先整理生成绑定尾随空白的候选已由最终重建替代。

- 原生 FFI 库测试 **63/63** 通过（524.98 秒）；其中含提交原子性、幂等重放、旧基线拒绝和失败回滚。另一个独立连接并发测试 **1/1** 通过：同一基线同时保存只有一个连接成功，历史仅增加一个编辑提交。两版 200 个原生源码输入按 LF 规范化后匹配；主机 Rust 测试不是 Android 所有 ABI 的执行证据。
- 两版最终设备各 **37 个不同方法** 通过，包括真实普通编辑组件新建/修改、重新导入稳定 Room/native 身份与目录、外部删除后不复活、未知字段/精确数值/附件保留、分组提交、外部修改拒绝、锁定/后台/关闭拒绝、提交后回读失败重试，以及外部发布、增量依赖、空闲同步和原生自动填充回归。
- 历史测试使用实际原生文件：编辑后导出增量并应用到独立 bootstrap 副本，核对密码与附件；再执行原生 revert 和 snapshot restore，核对原值及附件，并确认旧编辑基线不能继续保存。没有使用真实云账号。
- 实际 R8 Release：从前一轮的旧混淆 Release 在隔离用户中创建主密码、加密内容和原生库，再以同包名、同签名的新混淆 Release 覆盖升级，**从该轮旧包建库至升级验证结束，没有卸载或清数据**。独立探针调用映射后的生产 SecurityManager 和实际 UniFFI，核对原密码/旧密文、vault/object 身份、大整数、提交父关系、过期写入拒绝、新增/编辑、原生备份和独立恢复副本；随后另一个进程再冷读。Release 验证为生产加密/原生 API 路径，普通编辑 UI 的实际操作在 Debug 验证，不能冒称 Release UI 全路径验收。

## 初次失败与复测

- 普通首轮构建生成了 Debug 主/测试包，但选定 JVM 共 80 项中有 10 项源码 guard 失败（其中 guard 类 65 项）。9 项在精确 HEAD 的独立源码基线也失败；保留原断言和失败，不声称全仓 JVM 绿。第 10 项检查旧函数声明/身份语法，按有意的 UUID/suspend 接入更新后进入最终 18 项相关 JVM 测试并通过。基线失败明细见相邻 `guard-baseline` JSON。
- 首轮设备 8 项中 7 项通过；失败夹具尝试引擎禁止的原生类型转换。改为创建独立未知类型验证拒绝编辑，生产类型策略未放宽。后续 UUID/目录修复后，两版最终 37 项分别通过。
- `main-debug-03` 新增 reimport 测试的空 Flow 缺少类型参数，测试编译失败；补全类型后 `main-debug-04` 通过。旧失败日志保留。
- 为最终普通版升级重建合成基线时，仅清理了本任务用户 10 的上一轮普通版合成数据，并用原旧 Release 重新建库（seed02）；此后最终覆盖升级全程保留该基线。用户 0 未清理。重置回执最初因 Path JSON 序列化失败，原动作 stdout 与补充回执保留；未重复执行清理。
- 第一次 Release 主包 `main-release-01` 构建成功，但早于 UUID/目录最终修复；它不作为最终验收包。第一次升级探针编译使用过期 AGP classpath，修正为当前 classes.jar 后，旧包 seed 和最终升级各阶段通过。先前失败不覆盖、不删除。

- 追加审查发现撤销与回读发布之间的真实竞态：未修复包在确定性“读回时撤销”夹具中仍保留 pending 内容；同一回归在同步发布修复后通过。已提交的原生记录仍保留，未写 Room，pending/committed 均清空；不宣称取消能回滚已经提交的数据。为此重建两版最终包，早先 main-release-02 / fd-release-01 的成功构建不作最终验收。

- 最终普通 Release 编译成功后，复制映射证据遇 C 盘不足（WinError112）。本任务旧构建证据移至 D 盘并逐文件校验哈希，保留原路径 junction；从未变的 Gradle 输出补齐映射，并核对全部源码输入/三 APK。普通最终 Release 的 373 秒取 Gradle 日志，完整驱动耗时缺失；没有把证据复制失败隐去或称为代码构建失败。

- APK 原生库第一次直接哈希比对失败：Android 打包执行符号剥离，普通 ARM64 产物减少 8 字节。随后独立对两版全部三个 ABI 的 provenance 产物执行相同 NDK strip，结果与 APK 内库逐字节相同，Build ID 和 guarded-write 符号均保留。结果 JSON 分别记录构建产物与 APK 内库哈希，不将不同哈希冒称相同。

## 来源与边界

两版 17 个共享源码/测试/绑定/来源文件按 LF 规范化后相同；200 个 native source manifest 输入匹配；F-Droid 328/code35 元数据检查与 6 项发布脚本测试通过。普通版仍为 code12。

原生新增补丁已在独立 scratch 中应用到原记录输入，并逐一核对生成的 5 个文件与当前源码一致。普通版保留可追溯的三 ABI 库；F-Droid 从 vendored Rust 源码构建，不加入预编译 `.so`。原有 Glitter 验证 caveat 继续保留，本报告不扩张为 Glitter 全功能/硬件认证。

本轮使用合成库和 MuMu API35/x86_64 隔离用户。公共 API32 AVD 两次未能持续运行，随后复用专用 MuMu；没有新建公共 AVD 或删除配置/数据盘。没有验证物理设备、OEM/HyperOS、真实网盘、多设备长期同步、断电或全部旧写入入口。普通编辑加载同组账号仍需读取组成员；本轮不是大库性能基准，不承诺消除所有加载耗时。全分支保护采用保守冲突策略，即使无关对象的提交也可能要求重新打开表单。

已恢复原用户 0，只移除本任务的用户 10 及该用户测试应用；两份原有 Release 应用的 APK 二进制已恢复到原哈希，未卸载它们、未清理用户 0 数据。自启 MuMu index 2 已停止，配置和数据盘保留。清理回执记录恢复哈希与剩余用户；未以重新打开用户 0 原库冒充额外的数据保全验收。

首次移除用户 10 返回失败；重新确认已切回用户 0 且用户 10 已停止后，再次移除成功。初次失败日志与后续清理回执均保留。

328 仍未发布；没有提交、推送、打标签或交付 APK。既有 HyperOS 引用致谢和其他未提交工作保留。此前独立审查的 KDBX 类型重导入与 R8 Picker 首次认证不确定性不由本轮 MDBX 结果自动关闭。
