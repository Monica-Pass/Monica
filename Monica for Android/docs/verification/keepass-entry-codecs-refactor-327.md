# KeePass entry-field extraction — 1.0.327

2026-11-10，普通版与 canonical F-Droid 在各自 main 完成第二阶段拆分。327/code12、FD34 仍未发布；本次未提交、推送、打标签或交付 APK。第一阶段报告及原始证据保持原样。

## 改动

`KeePassKdbxService.kt` 本阶段从 9,508 行降至 8,787 行，累计从 10,287 行减少 1,500 行。迁移 30 个方法、54 个兼容字段常量，保留 5 个原服务入口。没有新增 Gradle 模块或依赖。

| internal 组件 | 行数 | 职责 |
| --- | ---: | --- |
| KeePassPasswordEntryWriter | 304 | 密码、OTP、SSH/Wi-Fi 等兼容字段与原生字段补丁 |
| KeePassSecureItemFieldCodec | 155 | 笔记、安全项目、混合登录 OTP 的字段与补丁 |
| KeePassBankCardFieldCodec | 301 | 银行卡字段读写、别名、有效期与自定义字段 |
| KeePassPasskeyEntryWriter | 107 | Passkey 原生及 KeePassDX 字段、补丁和时间 |
| KeePassEntryFieldSupport | 20 | UUID 解析、既有登录字段保留 |
| KeePassCompatibilityFieldNames | 69 | 54 个原有持久字段名 |

有回调的组件不是无副作用纯函数。OTP 解密、安全项目可移植内容、Passkey resolve/export 仍由服务提供窄回调，在原表达式位置同步调用。空 OTP 不提前解密；Passkey 保留 resolve→payload→export 顺序，DX 导出继续接收原 key reference。组件不缓存明文或密钥。原 `nativeMutation`、时间生成位置和异常传播保持。

锁、认证、缓存、来源修订检查、真实文件写入、事务、照片 I/O、Passkey protect 与远端编排继续由服务负责。算法、KDF、文件/变更集格式不变。银行卡别名优先级、自定义字段规则、REF 原文/保护位、混合登录字段、历史及附件保留策略沿用原实现。

## 验证

开始时两版完整源码清单与第一阶段最终受测版本完全匹配，因此继承每版 393 JVM/72 设备方法作为基线，不将旧结果冒充本轮重跑。另在未拆分普通版上执行 15 个已有字段方法，15/15、runner 20.603 秒；新增坏密文服务用例 1/1、runner 0.362 秒。新增测试包构建 92.890 秒，主包复用已保留的第一阶段 APK。

| F-Droid | 522.761 秒 | 423，0 失败/跳过 | 89/89；138.527 秒 |

JVM 覆盖原 KeePass 套件及本轮新增的 10 个字段/回调边界方法，并明确执行受影响的安全源码 guard、卡片模型和 Passkey 标志测试。两版本轮 Kotpass 为 UP-TO-DATE，没有计作重新执行；第一阶段各 7 项通过仅作为继承基线。普通第二次构建的主/设备测试包任务亦为 UP-TO-DATE，实际设备安装的是首次命令已成功生成并冻结的 APK。

设备为复用 MuMu0/API35/x86_64，独立应用 ID 和本任务 secondary user，仅合成数据。89 个不同方法包含第一阶段 72、补充 15 个字段消费者、1 个凭据交换消费者与 1 个新失败写入用例；其中两个快照 builder 用例为内存验证、一个旧 metadata 方法为 ViewModel 反射验证，其余包含服务/真实文件消费者路径，不把全部方法都称为文件写入测试。凭据交换用例同时涉及合成本地/MDBX及本机 MockWebServer Bitwarden，未连接真实账号。

新失败用例先成功写入受保护银行卡，再分别提交含合法前置修改和坏密文创建/更新的批次，要求报错来自 payload 解密边界、原 KDBX 逐字节不变；清缓存重读核对 UUID、字段、保护位和历史数量，最后合法重试成功。它在拆分前及两版拆分后均通过。10 个新增 JVM 方法直接验证银行卡别名/字段冲突/REF、空 OTP、回调失败、混合 OTP、Note 与 Passkey 调用顺序/原参数，使用合成数据而非真实 Keystore。

本阶段失败记录完整保留，具体原因与修正见下方记录；最终结果不抹去失败历史。
首次联合构建 `final-main-01` 已成功生成主/设备测试 APK，但在 JVM 测试编译处失败：新增银行卡与 writer 测试将 Kotpass `EntryFields.mapValues` 当作 Kotlin Map 转换使用，该成员仅接受 `EntryValue`。两处改为对 `entries` 使用 `associate`，保留原期望值和所有断言，生产及设备测试源码未改。原始 staging 测试源码、失败日志和实际生成的 APK 均保留；最终 JVM 以修正后独立结果为准。设备使用该次已成功打包的主/测试 APK，不能把联合命令称为全程成功。


## 一致性与审查

独立审查未以提取清单为真值，直接对照 before ZIP 与新源文件：28 个方法体原字一致，另 2 个方法仅有 3 处明确回调表达式替换；54 常量名称/值/顺序相同。还原已核对委托、初始化和 4 处接收者变化后，剩余服务 48,764 tokens、7,998 非空代码行一致。两版 11 个本轮源/测试路径逐字一致；普通版 5,170、FD 5,163 个既有文件原字节保留，包括其他任务的 Send/NFC 改动。

安全 guard 分别检查服务中的识别/解密/失败拒绝及回调绑定、新 codec 的 protected payload 和 mixed-TOTP 输出，原 MDBX/BW/WebDAV 断言保留。未通过拼接源码或删除断言来绕过位置变化。本地校验器曾因 Windows 默认 GBK 读取 UTF-8 注释失败，显式 UTF-8 后通过，无生产改动。

两版根/next 中英说明与 FD34 摘要同步，版本号不变；F-Droid 元数据及 6 个脚本测试通过，源码/文档空白检查通过。完整方法列表、源码/APK SHA 与运行数据见 [结果 JSON](keepass-entry-codecs-refactor-327-results.json)。原始构建、XML、runner、失败与独立审查保存在本地任务目录，未将截图、安装包或私有数据入库。
