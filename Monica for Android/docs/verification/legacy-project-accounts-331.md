# 旧 ZIP 多账号项目修复验证（1.0.331，未发布）

## 问题与最终行为

浏览器扩展已有 ZIP/WebDAV 格式能保留三条账号。Android 把只有 passwordGroupId、没有 monica.content.credential 的旧项目误当成同一账号，详情把全部密码放在第一个用户名下面，编辑恢复报用户名冲突或使用错误路径。用户已澄清第四条是手动新增，本任务以三条原记录为验收基准。

详情及编辑复用同一分组逻辑：显式账号沿用 groupId；旧式记录按精确用户名和 OTP 区分，不按密码去重、不修剪用户名。各组使用稳定身份，保存继续沿用原行 ID。混合缺失、损坏、冲突或未来元数据拒绝不安全编辑，读取本身不迁移写库。未知字段和保护位沿用现有模型。

实际故障注入发现项目逐行补偿保存不能原字节保留失败前的记录。最终实现把仅本地目标且原记录全部本地的项目保存纳入同一 Room 事务，保存开始的锁代贯穿提交，失败、锁定、取消完整回滚。项目互斥锁在进入事务前取得，避免与原生保存形成相反的锁顺序。跨存储写入继续走原路径，不宣称原子事务或文件副作用可整体回滚。

## 最终验证

普通版和 canonical F-Droid 的最终 Debug 主包、测试包、27 项针对性 JVM 均通过；每版 46 个不同设备方法通过。设备为已运行 MuMu/API35/x86_64 的本任务隔离用户，所有账号和密码均为合成数据。

- 真实扩展导出 JSON 经 Android ZIP 解包和 BackupRestoreApplier 全覆盖恢复两次，始终恰好三条；损坏输入拒绝并保留原库。
- 实际 Compose 详情三账号分别显示；修改第二账号用户名，保存，再从第三条进入重存；原三条 ID、密码及各行未知保护字段保留。正常与 1.5 字号截图已检查，仅留忽略目录。
- 真实 ViewModel 保存后 Android 加密 ZIP 导出、独立新进程读取通过。扩展使用生产 decryptAndroidBackup/readAndroidBackup 读回两版最终 ZIP，三组账号、密码与 metadata 均保留。前一诊断扩展八个 plain/V1/V2/WebDAV 序列化用例通过；本轮没有修改扩展生产代码。
- 保存失败、锁定、取消三项新增故障注入验证原行、原密文、自定义字段完整相等，取消无成功回调。另包含本地多目录、相同密码不去重、显式账号编辑、KDBX 原生读写、合成 Bitwarden 往返和失败回滚回归。
- 两版实际 R8 混淆 Release 用相同隔离包名和相同本地测试签名覆盖旧 R8 包，不卸载、不清数据。旧包模型哈希与本任务修改前一致；旧包真实 UI 创建记录和加密备份，升级后验证错误密码拒绝、原主密码、旧记录、新写入、不同 PID 冷启动和旧备份恢复。普通版在事务补强前做过一次初验；最终验收前覆盖回原旧包确认数据仍在，再安装最终包。

## 失败与边界

- 旧分组模型回归 17 项中 3 项预期失败；修复后 17 项通过。首次分组改动暴露部分 metadata 门控，改为拒绝混合 metadata 后通过。
- 普通最初联合 JVM 构建有 9 个既有源码字符串 guard 失败；用实际当前 AGP 编译测试类对修改前源码核对，同样 9 项失败，未删断言。早期错误使用旧 tmp Kotlin class 的 12 项失败对照不计有效结论。
- 普通第一次 ZIP 设备用例把恢复后重新加密的字段直接与明文比较而失败；只改测试按现有生产解密入口比较，保留首次日志。没有放宽生产加密规则。
- 新增旧账号失败/锁定两项测试在事务补强前确实失败；最终两版三项故障测试通过。main-fixed07 构建期间源文件改变，明确废弃，不作为最终证据；最终构建源哈希冻结一致。
- 扩展检查 ProjectCredentialStorageTest 的两个 MDBX 方法失败：初稿缺少原生编辑会话；临时补齐会话后继续暴露原生编辑基线及附件迁移失败。临时夹具归档并恢复原测试，生产 MDBX 路径未改。这两项未解决，不能称全部存储回归通过；本次结论限定 ZIP 恢复到 Monica 本地库及已列通过路径。
- Release 验证是本地测试签名及合成数据，非生产签名、用户原机、真实远端或全部 OEM 验收。R8 一般升级流程与 Debug 三账号故障测试分别记录，不将前者冒充 Release 故障注入。
