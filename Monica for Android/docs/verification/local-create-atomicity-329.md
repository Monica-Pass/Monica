# 本地多密码与批量创建失败重试（未发布 1.0.329）

2026-11-18，普通版 code 12，F-Droid code 36。修复的是可复现的保存故障，不能仅凭反馈截图认定用户经历过保存失败，也没有删除或合并任何已有项目。

## 行为

纯本地多密码保存将密码行和自定义字段放在同一个 Room 事务。全本地批量创建，以及一次新建到多个本地文件夹的操作，也整体提交。字段写入报错时不留半条记录；写入前后检查取消与发起保存时的会话代数。一次失败的编辑保留原 ID、密文和字段。对同一用户明确选择的两个文件夹，新建和重开编辑都保留每个副本自己的项目标识。

一个项目的多个密码或登录凭据仍可属于同一项目；用户明确批量创建的两个相同输入仍是两个独立项目。没有按标题、账号或密码内容合并项目。此修复不提供跨外部存储事务，也没有改变加密格式、表结构或修复历史重复数据。

## 对照与结果

| 场景 | 观察 |
| --- | --- |
| 修复前：普通版注入一次真实 Room 字段写入故障 | 多密码、批量首条及真实编辑页重试三项零残留断言全部失败。此前诊断中，同一草稿再次点击保存，从两个密码行变成四行、两个项目。 |
| 第一轮：两个本地文件夹 | 普通版首批 21/22 通过。失败发生在重试后的项目标识；回滚断言已通过。修正新建标识后，两版各 22/22 通过。 |
| 重开编辑对照 | 同一个加强后的测试在上一轮普通版重现：两个文件夹的四条原记录重存后共用一个项目标识。最终包从第二个文件夹重开编辑，两个文件夹的原记录 ID 和项目标识不变，密码均更新。 |
| 最终两版 | 各 9 项相关 JVM 测试通过。MuMu Android 15 / API 35 / x86_64，各 22/22 项设备回归通过，runner 普通版 26.800 秒，F-Droid 24.531 秒。包含真实编辑页失败后点原保存按钮、批量第一个或第二个字段写入失败、取消、锁代变化、读者看不到部分记录以及相邻的 Bitwarden 新建路径。 |
| 覆盖安装与冷启动 | 普通版用修复前代码写入两条合成密码行，覆盖中间修复包后增加一条，再覆盖最终包冷读；F-Droid 用上一轮修复候选包创建夹具，再覆盖最终包写入并冷读。各自核对不同进程、旧 ID、旧密文摘要、解密后的值与受保护字段。 |

实际运行使用隔离 applicationId 的 Debug 包。普通版最早的测试夹具因缺少参数编译失败；一次旧版建库 runner 通过，但驱动曾误判单数 `OK (1 test)`。F-Droid 中间候选构建曾复用测试 APK，安装驱动因只记录新时间戳而漏报；核实 Gradle 的 UP-TO-DATE 结果、包名与既有 SHA-256 后才安装。原始失败回执保留在本地。最终包及报告索引见[验证回执](local-create-atomicity-329-result.json)。

设备只使用合成数据，卸载本任务四个隔离包后，用户与用户 0 包清单均和开始前一致；只停止本任务启动的 MuMu 实例，没有使用公共 AVD。没有验证真机、R8 Release 升级、系统掉电或多存储原子性。
