# 密码编辑加载门控修复（未发布 1.0.328）

2026-11-17。修复编辑已有密码时原记录及关联内容尚未加载完成便允许保存，导致空原 ID 集合进入新建路径的问题。该问题先前已在合成本地 Room 数据上复现；不能确认它就是未提供平台、版本及库类型的反馈者所遇到的原因。

## 实现

- 编辑和复制来源完整加载前禁止保存，包括关联账号、原生保存基线、自定义字段及网址规则等后续读取。编辑保存还要求原 ID 集合包含当前编辑目标，项目加载失败也不可提交。
- 来源缺失或读取抛错时保留原数据并保持禁止保存，不再回退为空的新建表单；使用现有失败提示和无值诊断，提示明确调度至主线程。
- 读取直接归属 LaunchedEffect，关闭或替换编辑页时取消。加载完成标记仅在内存保存，恢复表单时必须重新读入源身份；保留现有锁定卸载编辑器与存储端授权保护。
- 保存按钮通过无障碍语义声明不可用；原按钮点击门控保留。正常新建与显式复制仍使用原保存流程。
- 不改变数据库结构、加密、同步协议或现有条目；不自动合并或删除已存在的重复项。普通版与 F-Droid 的生产编辑页和新增测试字节一致。

## 实际验证

使用既有 MuMu API35 / x86_64 的独立测试用户与合成数据。普通版以临时 applicationId `takagi.ru.monica.editload328` 构建验证，避免覆盖设备原用户现有普通版；F-Droid 使用其包名。均为 Debug，主/测试包签名和实际包名已检查。

- 两版最终主/测试打包与所选 9 JVM 测试通过：普通 413.000s，F-Droid 313.721s。JVM 为 8 项 credential save planner 和 1 项原有跨目标保存检查。
- F-Droid 19 项设备测试全部通过，runner 43.753s；另 1 项大字号编辑器测试通过 1.419s。普通版同范围含大字号共20项整批通过，runner 35.335s。
- 新增 9 项真实 Compose/Room 测试：慢关联查询保存不新增；后段字段加载前不写、加载后保留重复字段及保护位；后段读取失败保留原记录；源缺失不变新建；恢复表单重新等待读取；加载中取消；锁定后不可复活草稿；正常新建；显式复制。成功编辑核对单一原 ID、密码更新、标题/备注/字段保留，并经另一 Room 句柄读取持久化结果；不是跨进程冷启动验收。
- 既有回归覆盖本地多密码/旧 metadata/冲突保留/附加账号编辑、Bitwarden 真实编辑器重开仍同 ID 和 MockWebServer 一次创建、3 项 Bitwarden 本地事务，以及真实加密 KDBX 编辑器创建/重开/修改/清空账号备注并保留原生身份。未用这些结果声称复现了 Bitwarden 或 KDBX 的同一竞态。
- 中英 root/next 发行说明与 F-Droid35同步；F-Droid元数据和6脚本测试通过。

## 初次失败与限制

最初 F-Droid 主/测试包均打包成功，但联合 73 JVM 中 9 项历史源码 guard 失败。使用改动前编辑页及其他原样源码建立只读副本，执行相同已编译的 9 个测试方法，全部在同一断言失败；未删改断言。最终只重跑相关 9 项，不能称完整 JVM 套件全绿。

F-Droid 首轮新设备测试 8/9 通过，失败是后段读取异常后 Toast 在 Compose 测试调度线程调用。生产提示显式切回 Main 后，完全相同测试 APK 的 9 项连同既有回归全部通过。原失败日志与测试包哈希保留。普通首轮构建在 34.806s 主动取消自有 Gradle 客户端以同步此修正，没有把中断计为通过。

普通最终 Gradle 构建成功 6m53s，记录脚本随后因假设普通与FD安装包文件名相同而失败。改读实际 output-metadata.json 后核对包名、ABI、签名与哈希并安装验证；没有为了脚本失败重复构建或改名冒充其他产物。

先前原始复现为一条记录变两条且原密文不变，正常加载对照仍一条；本轮新增慢读取测试确认禁止早保存、放行后同 ID 正常更新。本次没有真实用户库、真实云服务、MDBX 编辑路径、实体机/OEM 或新的 Release/R8 升级验收；没有修改启动、密码学、数据库格式或依赖。其他独立审查发现（KDBX重导入类型、首次R8 Picker退出）不在本修复范围，未声称已解决。
