# Monica 键盘按键震动反馈修正（2026-10-31，1.0.323 未发布）

用户反馈已开启按键震动仍无震感，并明确不是仅前一台 HyperOS 1 手机。此次处理的是键盘通用触感路径，独立于系统保存兼容开关。

## 发现与范围

原 MonicaKeyboard 创建 HapticFeedbackHelper 时仅传 Context，没有传入当前 View。按键确实会调用 performClick，且开关经 MultiProcessDataStore 序列化、独立 :ime 进程订阅再传入键盘；但没有 View 时会退回普通20ms振动请求。Android 的 Vibrator.vibrate(VibrationEffect) 文档注明应用应处于前台，输入法更适合由其窗口使用 KEYBOARD_TAP 标准触感路径。

旧包实际输入法窗口按下 q 后，API32 模拟器的20ms请求状态为 finished，表单也收到 q。因此此次没有复现所有真实手机的物理“不震”，不把该模拟器记录宣称为后台拦截证据。模拟器也无法确认手感强度。两项旧实现回归均失败于窗口收到的触感请求为空（期望 KEYBOARD_TAP=3），精确锁定了未连接窗口的代码缺口。

## 改动

普通版和 canonical F-Droid 仅在 MonicaKeyboard 中获取 LocalView.current，将它传给已有 HapticFeedbackHelper，并纳入 remember 的依赖。开启时由实际输入法窗口发送标准键盘触感；关闭时不发请求，设置变化立即更新按键回调。触摸按下和无障碍点击、字母/数字/符号/操作键共用同一路径。沿用原系统触感策略，不使用忽略系统设置的标志，不增加强制振动或更改其他页面助手。默认仍关闭，设置存储格式、PIN随机/预览、输入内容和锁定规则保持。

本次无可见布局或新字符串变更，无新增设计草图；现有说明已更新普通版与F-Droid中英文未发布记录及fastlane30。

10项设备用例包括新增2项实际按键到宿主View的反馈检查、既有6项键盘输入/模式/长按/预览/布局检查、1项真实设置开关持久化、1项独立输入法进程的数字/字母输入与实时跨进程选项。新检查覆盖关闭→开启→关闭、触摸与无障碍点击，以及数字/符号/操作键；录制View仅用于精确验证调用，不代表测量电机。另单独使用实际输入法窗口和合成空表单检查系统震动记录，区分旧20ms普通请求与新KEYBOARD_TAP路径。

真实按键的最终系统记录为预定义 CLICK、USAGE_ASSISTANCE_SONIFICATION、Flags=0、status=finished，按应用UID归属，证明当前窗口反馈到达平台。旧请求则是20ms Step、Audio Usage=USAGE_UNKNOWN，同样为finished；这项对照只确认路由修正，不证明旧请求在所有设备必然被拒绝。安装包更新期间曾观察到输入法回落Gboard，截图检查发现后重新明确选择Monica，最终记录前再次核对组件，未把Gboard的反馈当作Monica结果。

原实现负向对照2/2失败后才应用生产修正。初次宿主脚本使用了系统不接受的完整IME名称，改为系统清单提供的缩写；模拟器启动期间System UI/Dialer发生ANR，一次挡住表单，释放闲置编译资源并关闭弹窗后继续。普通uiautomator dump只提供应用节点、没有输入法节点，后改用原生截图定位真实按键；这些驱动/环境失败均不计入通过，也不视为用户震动故障复现。

普通版最终首轮混合运行10项时，真实输入法用例在等待表单实例阶段超时，其余9项通过。保持同一APK单独运行该用例后通过，没有更改生产或测试逻辑；未确证全部时序原因。F-Droid提前将Compose与实际输入法用例分为两次instrumentation执行。此前偏好测试只证明开关可写入，新增回归补上了按键到窗口触感出口的检查。

两版各2个本轮生产/测试文件哈希一致。主程序版本为普通版1.0.323-26103112-95/code12、F-Droid1.0.323/code30。本次未追加R8 Release构建或实体手机电机验证；真实机型、系统触感关闭和硬件强度仍受平台控制，不能保证每台设备均有可感知震感。
