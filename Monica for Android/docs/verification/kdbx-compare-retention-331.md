# KDBX 比较内容保留补充验证

普通 Android 与 canonical F-Droid 的未发布 1.0.331。此记录补充初次 [比较与合并验收](kdbx-compare-331.md)，不替换或隐藏此前失败。两版均已完成下述限定验收与自有测试环境清理。完整计数、方法与产物 SHA-256 见 [结构化结果](kdbx-compare-retention-331-results.json)。

## 复现与修正

完整加密文件复核确认三个原实现遗漏。修前 3 个定向测试全部失败；重复完整引擎批次为 18 通过、3 失败。日志保留，未将失败算作通过。

- Auto-Type 的空 `KeystrokeSequence` 表示继承默认序列，空窗口字符串也必须保留。原读取器把存在但没有文本的节点误作缺失，丢掉整个关联。读取器现在区分空节点与不存在节点，保留条目及历史的规则。比较预扫描拒绝缺少必要节点的关联，并核对解码前后的关联总数。
- KDBX 3.1 的 ISO 时间可含亚秒精度。原比较摘要只取整秒，会把仅亚秒不同的当前条目视为相同，并折叠有效历史。摘要现保留完整 Instant 精度，生成结果后重新读取也用完整精度校验。
- 原生布尔字段中的未知字符串可被底层转换成 false；未知组覆盖策略可被当作继承。比较预扫描现在检查明确的 True／False 与合法 Null 组策略，未知或空策略值阻止输出。普通开库的布尔解析未因本补丁改变。

修正未降低 KDF、加密、授权、修订和锁定要求。结果仍为独立加密新文件；两份输入保持原字节。

## 测试范围

两版各 63 项 JVM／底层方法通过：24 原生比较、5 文件传输保护、3 XML 读取、10 原生修改、17 同步、3 有界解码、1 底层 Auto-Type 读取。普通版首轮测试过滤器误写同步类名，首轮实际 46 项；单独补跑正确的 17 项，未声称首轮包含同步测试。

新增用例覆盖 KDBX 3.1／4.x 当前条目和历史的空规则、空窗口、完全空关联、相同秒内仅差一纳秒的历史与元数据，以及合法大小写布尔值和 Null 继承策略。38 组完整加密负向输入覆盖 12 种策略的未知／空／数值字符串及两种缺失关联节点，并验证阻止输出与来源字节保留。

两版各 70 个不同 MuMu 方法通过：24 原生比较、7 控制器、4 来源、11 Compose 及24既有 KeePass 兼容／当前文件合并／历史回归。覆盖取消、锁定、后台、迟到结果、来源变化、未授权目标与失败输出清理；现有管理入口、双栏身份、返回和系统选择器状态保留亦通过。本轮没有新增界面设计。

## Release 与独立互操作

两版实际混淆 Release 均已构建并通过下述流程。实际混淆 Release 采用隔离包名与测试签名，从前次已验收的 R8 包通过界面创建合成记录和加密备份，再覆盖安装本次包。已核对签名、实际 x86_64 ABI、安装 UID 不变、错误密码拒绝、原密码解锁、旧记录读取、新记录写入、旧加密备份恢复与多次新 PID 冷启动；未卸载或清数据。

独立输入由 PyKeePass 4.1.1.post1 生成，使用公开 KeePassXC KDBX 3.x 夹具的头结构，替换为本任务合成分组与条目并明确设为3.1；不是用户密码库。保留了公开夹具的2条删除记录，并额外核对它们在输出中不变。输入包含4条 Auto-Type 关联（含空值与重复）、仅一纳秒不同的两份历史、受保护自定义字段和附件。输入经 PyKeePass 与 KeePassXC CLI 2.7.11 重开核对。两版均通过真实管理入口和 DocumentsUI 选择／保存，输出由两工具独立读取。原始 XML 核对确认当前条目及3份历史各保留4条关联，两个仅一纳秒不同的旧历史和未选中的另一侧当前版本完整保留；同时核对当前纳秒时间、UUID、受保护字段和附件原字节。所有3份输入前后字节及 SHA-256 一致。异常保护策略文件在两版 Release 界面均显示受阻，保存按钮禁用。

## 保留的环境与驱动失败

- 最初复制本地驱动时未指定 UTF-8，读取失败；仅修正驱动编码后继续。
- 首次 Release 建库时 MuMu 推广浏览器抢占前台，驱动拒绝继续。accessibility 与窗口记录确认是 Chromium；无对应 Monica 崩溃，原应用数据保留后继续。
- 独立夹具初次只修改 PyKeePass 的解析头，RawCopy 仍保留旧版本字节；同时库默认带有一条空 Auto-Type 关联。明确修改头字节并核对完整4条规则，重新经独立工具验证后才使用。
- MuMu `content insert` 成功但 stdout 为空；驱动改为查询任务用户下唯一的合成文件名和目录得到 URI。传输／读取按完整字节与长度核对，工具返回139及诊断尾部单独记录，不计为应用崩溃。
- 初次 Git 空白检查在错误工作目录使用相对路径而失败；使用明确绝对仓库路径重新检查。F-Droid 元数据与6项脚本测试通过。
- 普通版输出首次读取时长度／诊断尾部断言未通过，未留存该次完整原始 stdout，原因未完全确定；未重新生成输出。随后对同一文件重新查询长度并读取成功，两独立解析器和内容断言通过，保留失败及诊断回执，不称首次读取成功。
- 受阻按钮的初次 UI 断言检查了按钮内部 TextView 的 enabled 属性。实际可点击父节点为 disabled；修正驱动以最近可点击父节点为准，没有修改产品或放宽禁用要求。

- 清理时首次立即删除已停止的合成用户失败；确认原用户0已恢复、用户10不再运行后重试成功。首次命令与失败回执保留，未改动其他用户。
