# KDBX 比较与合并：选库、认证与平滑收缩

普通版与 canonical F-Droid，未发布 1.0.331。本记录补充原有比较引擎与内容保留验收，针对本次用户指出的选库和交互问题。两版实际 Release 与自有测试环境清理均已完成，结果和产物哈希见 [结构化记录](kdbx-compare-experience-331-results.json)。

## 交互与认证

- 两侧数据库卡片打开 M3E 底部选库面板，列出 Monica 已注册的内部／外部库及位置、认证状态，另有系统文件入口。卡片使用主题色层次、图标与整行点击区域，支持窄屏和大字号。
- 只有当前有效的原生认证会话可复用；已保存密码或曾经解锁不能单独作为授权。比较前重新核验原生会话、全局锁代、数据读取代和来源；不为显示选库列表主动解密或打开数据库。会话释放、过期或锁库后重新输入凭据。
- 系统文件选择器选入的外部文件必须提供本次凭据，即使它碰巧对应已经认证的注册库。Monica 中已认证的注册外部库与内部库一样可复用当前会话。
- 卡片由一层主题 spatial 动画负责高度变化，认证后密码控件立即移出内容树，外容器平滑收缩；反向切换从当前高度继续，遵循 Compose 系统动画设置。锁定和后台撤销仍立即生效。
- 合并继续生成独立加密新库，重新解密验证并校验输出字节。两份输入不覆盖，来源变化、取消、锁定、已有非空目标和受阻写入保护保留。

参考 ImageToolbox 提交 `ab763ce76effd13ae3b8c7cfea37835eb9e0f8b9` 的内容尺寸动画与分组容器交互，使用 Monica 现有 Compose／M3E 组件实现。可编辑 Canvas 和原生截图只留本地忽略目录。

## Debug、JVM 与设备验证

两版各 64 项 JVM 检查通过：24 比较引擎、5 文件传输、3 XML 读取、10 原生修改、17 同步与5语言资源覆盖。新增4条文案覆盖21组资源配置、每版84个值；29个生产／测试／资源改动路径两版字节一致。

两版各76个不同 MuMu/API35/x86_64 设备方法取得通过结果：17界面／动画、24加密文件比较、7控制器、4来源及24既有 KeePass 兼容／当前文件合并／历史回归。F-Droid整批76/76；普通版分批取得通过结果，首轮失败见下文。

界面使用真实生产页面、控制器和加密合成文件，覆盖已认证内部＋注册外部库免重复输入、系统选入同一文件仍要求密码、错误密码拒绝、单库锁定和全局重新锁定撤销、实际选项与结果重新打开、历史与原文件字节、返回／取消／后台／迟到结果、管理页双栏身份和系统选择器生命周期。此组的选择器结果由测试注册器投递，不冒充真实 DocumentsUI。

两项动画测试在320dp、浅色正常字号及深色1.5字号下，明确断言展开高度＞中间高度＞收缩高度，并验证反向和中途打断不跳到端点；同时断言密码控件立即消失。两版原生页面与代表性动画帧已查看。

## 实际 Release

两版 R8 构建完成；先在旧 Release 经界面创建合成记录和加密备份，再以同签名／同包名覆盖安装，核对 UID 不变。实际验证错误密码拒绝、原密码、旧记录、新写入、旧加密备份恢复和不同 PID 冷启动，未卸载或清数据。使用隔离包名和测试签名，不代表正式发布签名安装包升级。

两版真实管理页进入比较，注册外部库显示当前认证；底部面板显示位置与解锁状态，经 DocumentsUI 另选文件后只需另一侧凭据。通过真实选择、审阅和系统保存窗口生成新 KDBX3.1。PyKeePass 与 KeePassXC CLI 独立重开，核对所选密码、UUID、保护字段、附件字节、3份历史、纳秒时间、每版本4条 Auto-Type关联及删除记录。3份输入逐字节保持不变。Debug界面用例另覆盖内部库与已认证注册外部库组合。

## 首次失败与修正

- 普通版第一次界面组5/17通过。旧测试按“选择数据库”文字匹配，改版后同时匹配页面说明与按钮；修为明确右侧选库控件。新增原生认证夹具误用内部库绝对路径，按生产约定改为 filesDir 相对路径。没有修改生产策略或删除断言；保留首轮APK与日志，后续17/17通过。
- 普通版首轮核心选择器误写两个测试类名，50个实际方法通过，另有2个类加载失败。使用正确类名补跑9/9，去重总计76；未称首轮整批全绿。
- Release旧包首次建库驱动预期英文，而新合成用户继承繁体系统语言；仅为本任务隔离包设英语后继续，保留初次失败。
- 实际 Release 驱动沿用了旧“Import”按钮，当前独立打开页面为“Open Existing”；根据真实控件修正驱动后继续，未修改产品。
- 初次空白脚本检查整个大型服务文件，发现本轮之前已有尾空格；按任务开始副本核对新增的515行均无尾空白，两版Git差异检查通过，没有为排版重写安全服务。
- 本地文档同步脚本假设 F-Droid 已有用户指南，遇到文件缺失停止；随后明确新增指南，补齐两版说明。首次执行的元数据检查不能替代修改后的复检；最终元数据与6项脚本测试另行记录。
