# 313→330 本地旧记录读取失败调查（尚未定位个案）

## 结论

用户确认同一台手机仅覆盖升级，330仍能用原主密码登录，但旧记录密码不可读。导出界面显示Monica本地库73条记录，并因敏感字段读取失败取消ZIP导出。尚不知道受影响记录是否覆盖全库。

本轮没有复现该个案，没有修改生产加密、认证、迁移或导出代码，没有承诺331能够恢复。已请求仅提供330的 `event=data_read_failure` 与 `event=data_read_detail` 诊断行，包含格式、异常类型及可用的Keystore错误码；不需要密码、数据库或完整日志。

## 源码已核对

- 313已经使用MDK/C2/V2格式；330保留对应读取。“版本跨度大”不足以证明根因。
- 详情密码不可读和编辑页兼容提示均可能来自底层解密失败，不能只凭提示判断整库损坏。
- DatabaseArchiveExporter的敏感字段处理在失败时取消导出，避免生成丢失密码的备份。该路径传入空标题，导致错误中显示“未命名条目”，不能据此认定原记录无标题。
- 330密码认证成功后可以把旧100000次PBKDF2保护升级到600000次；325固定使用旧参数。此项是源码结论，本轮没有在设备上降级325。
- Room数据库版本：313=78，324=80，325/326/330=85；324无85→80降级迁移。降级闪退与旧密码读取失败需分别判断，本轮未实测324降级。

## 保留的失败和环境限制

313首轮4GiB构建堆耗尽，在记录heap后停止核对过的自有Gradle进程；6GiB重试1032.930秒成功。330构建910.979秒成功。313仍有旧R8 Kotlin metadata警告，保留日志。

313 ZIP在解密打包后进入系统选择器，但选择Downloads根保存时被DownloadStorageProvider拒绝URI写权限，产生0字节文件且自动删除也被拒绝。此失败与用户的敏感字段读取失败不同，未修复其根因，不能算313备份保存成功。330改用内部Documents完成保存和回导，不声称Downloads问题已修复。首次截图因安全窗口为黑图，不计视觉验收。

MuMu和公共AVD都有保留用户的官方包，不能直接覆盖官方APK；曾启动公共AVD只读检查，确认冲突后停止，未安装或改其应用数据。最终恢复MuMu用户0和原280密度，仅移除自有用户13及隔离包，原0/10/11/12/16与官方安装版本/路径/时间保留，shell仍2000；停止本任务启动的MuMu0及独立ADB15078，保留模拟器配置和盘。清理回执留在本地任务目录。

没有提交、推送、发布或交付安装包。当前调查等待用户个案的无值诊断行。

清理首次在用户停止后立即删除失败；确认已停止后重试成功。系统随用户移除了隔离包，后续显式卸载返回未安装。官方包元数据比对中的自有用户13未安装占位时间随用户删除而消失，其余安装路径、版本、更新时间和原用户实际安装时间一致。原失败及最终核对回执均保留。
