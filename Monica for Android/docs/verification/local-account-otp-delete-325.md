# 本地多密码账号删除验证器后的保存修复（1.0.325，未发布）

后续（2026-11-06）：用户进一步提供的JSON证实还有相同账号字段重复导致的拒读，旧删除修复未覆盖该形态。新的读取兼容、旧部分OTP保留和实际保存复测见 [本地项目metadata后续报告](local-project-metadata-325.md)；本文保留此前真实范围和结果。

## 结论与范围

已在合成数据中复现用户怀疑的路径：本地同一账号含两个密码且具有账号 metadata，删除绑定验证器只清掉 boundPasswordId 对应的一行，另一行仍有 OTP。再次打开真实编辑页并点击保存时，账号字段一致性保护拒绝保存。两个密码可正常读取，与用户描述相符。原始用户日志没有本次异常栈，因此不能证明用户文件只有这一种问题。

用户提供的 KeePass 截图仍显示“2 个密码”堆叠，不能据此认定项目已被拆散。第二行的验证码与残留 OTP 字段相符，但本轮没有读取或修改用户手机、KDBX 或真实账号，也没有更改原生 KeePass 删除路径。用户使用 1.0.325-26110412-22 / API36，是否为 R8 构建未知；本轮使用 API32 / x86_64 / Debug 合成夹具。

## 改动

- TotpViewModel 的本地密码绑定删除进入 Room 事务，沿显式项目来源及账号 metadata 定位同一账号，不按标题、用户名或密钥相似性合并账号。
- 若同账号还有另一份有效的等价绑定，保留账号 OTP；删除最后一份绑定时一次清除各密码中匹配的 OTP。批量删除排除整批已选择的绑定。
- 匹配包含 OTP 类型、秘密、算法、位数、周期、计数器和 mOTP PIN。独立账号、其他来源、不同 OTP、已替换的绑定、密码原密文及 metadata 保留。
- 先读完并解析所有匹配字段再写；无法读取或 metadata 冲突时中止删除并保留原数据。原编辑器严格冲突保护不变。
- 已经部分清空的旧账号不会自动迁移。明确删除剩余的对应验证器时可以完成清理；测试对此使用单独标注的旧残留夹具，不把它冒充原始复现。
- 数据库 schema、加密算法、KDF 与存储格式不变。普通版和 canonical F-Droid 的 3 个生产文件及 2 个设备测试文件同步。
