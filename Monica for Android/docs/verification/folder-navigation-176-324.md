# Folder hierarchy and sorting: 1.0.324 verification

Issue: https://github.com/Monica-Pass/Monica/issues/176#issuecomment-6561684371

The overview displays top-level folders. Opening a folder or database uses scoped hierarchical browsing, without changing the saved classic/hierarchical layout preference. Every folder in the current layer remains in one continuous block above the direct entries. A–Z and Z–A sort only that block; no letter headers split it. The existing overview preview and View All entry remain available, while the entered hierarchy does not truncate its folder block. Parent navigation uses the existing retained history and scroll restoration.

The complete overview catalogue and numeric aggregation indices remain available for counts. Local children are hidden only from the top-level display, and a folder without an existing local parent remains reachable. MDBX uses its parent IDs. Bitwarden folders remain flat even when their names contain a slash. KDBX names with encoded slashes remain single groups; child navigation and subtree counts use group UUIDs and read-only parent UUID metadata. Identical names and paths do not merge separate parent identities. Ambiguous path-only items remain in aggregate item views and are not assigned to a guessed UUID folder. Direct-entry filtering preserves source boundaries and excludes child layers.

Browsing and sorting do not call the database writer or change credentials, KDFs, encrypted formats, permissions or write-conflict checks. The new saved field is a navigation Boolean appended to the compatible saver. Existing authentication and lock invalidation remain active. The real synthetic KDBX case navigates both equally named parents and their separate children, includes a group name containing a slash (the encoding/display contract is asserted in JVM coverage), locks the active source and verifies the original ciphertext bytes are unchanged.
