# 本地文件夹层级 — 1.0.328

普通版与 canonical F-Droid 的“管理原始信息”改为按本地分类路径逐层显示。文件夹名字含 Bitwarden 不会改变其本地来源。版本保持未发布 1.0.328，普通 versionCode 12、F-Droid 35。

## 行为与边界

- `父目录/子目录/第三层` 先显示父目录，进入后显示直接子目录；父分类没有实际记录时生成只读导航节点，浏览不写入数据库。
- 保留实际分类 ID、记录归属和字段。新建支持当前层级；重命名和同一本地库内移动按路径边界更新全部后代，拒绝循环、冲突、歧义路径和外部数据库共用分类。
- 显式把记录移到原本不存在的父分类时，才在原事务与解锁检查中创建实际分类；刷新及旧返回历史仍能解析原导航位置。
- 删除遍历选定子树，沿用原修订校验和本地删除策略。未知原生属性、外部来源及原有跨库安全边界保留。
- 本地嵌套文件夹复制与向本地复制原生嵌套目录继续在写入前拒绝；本次没有实现该复制能力。多个数据库之间不承诺原子回滚。

## 额外发现：ZIP 定向导入不保留分类

**目录路径随备份恢复的检查未通过，不能把全部额外检查称为全绿。** 两版各从实际 Release 页面导出一个加密 ZIP，再通过系统文件选择器、恢复确认及备份密码恢复合成记录。

普通第一次恢复原有同一记录显示 0 导入、1 跳过。随后平台夹具先核验原密文及分类，只移除本任务生成的那一条匹配记录，再走真实恢复流程；主密码、分类、其他数据及新建目录保留。恢复后密码内容可解密、记录数正确，但定向本地导入的 `categoryId` 为 null，记录落在根目录。F-Droid 也按同一受限流程验证。

源码原因独立于管理页面投影：`DataExportImportViewModel` 对指定目标使用 `importDataOnly`；`WebDavHelper` 在该模式下不解析实际分类归属，`ImportDestinationWriter` 只使用明确的目标文件夹。此次保留该既有导入行为，未扩展导入协议或修复它。原路径断言及失败日志保留；另加只验证恢复内容和当前根目录行为的检查，不将其替代为“目录恢复通过”。后续应独立设计并验证 ZIP 分类映射、重复分类与跨来源导入。

## 保留的探针失败

- 普通 seed-01：R8 删除未使用 DAO 方法；seed-02/03：协程参数收紧为实际 ContinuationImpl，普通 Java 动态代理不匹配。使用实际残余类型适配后 seed-04 通过，未修改生产或放宽数据断言。
- F-Droid seed-01：其 `invokeSuspend` 也被改名，初始适配器未按该版本 mapping 覆盖，出现 AbstractMethodError；按本包 mapping 修正后 seed-02 通过。
- 普通 restored-01/02：目录归属断言失败。单独的 restoredData 仅确认密码恢复及现有根目录行为；目录恢复仍不算通过。
- F-Droid 首次 UI 恢复驱动错误地寻找普通版专有的 Files 标签，尚未开始导入便停止；根据实际 F-Droid 页面继续选择文件，完成 1 导入、0 跳过、0 失败及冷进程内容检查。没有改动 F-Droid 产品功能以迁就驱动。
- 显式拟议标签检查拒绝未发布说明，属发布保护；默认开发元数据检查及 6 项检查器测试通过。没有创建标签。
