# KeePass 页面、数据库排序与解锁布局 · 1.0.331

2026-11-25，普通版 code 12／F-Droid code 38，未发布。

本轮只收尾三项 UI：KeePass 打开／新建改为独立页面，复用现有 MonicaPageContent 进入与返回过渡、纯色表单和连接按钮；KDBX／MDBX 磁贴长按直接排序；密码验证期间及后台清空后保留禁用的空输入框，避免移除组件造成的一帧跳动。敏感内容仍按原生命周期规则清空。

用户明确忽略“对比其他 KeePass 新建页并补齐功能”。前次新增的数据库说明字段、原生说明写入、参数重置、新凭据／KDF 校验规则及独立文件命名／清理管线均已撤回。原有创建字段、默认值、规范化和原生创建函数沿用任务基线；创建／打开／密钥生成增加结果回调及页面持有的取消句柄，用于失败留页、成功返回和拒绝过期 UI 回调。没有加入其他数据库功能。

排序通过 Room 事务仅更新现有数据库引用的 sort_order；筛选来源只替换原有顺序中的对应位置，不写 KDBX／MDBX 文件，不修改条目、凭据、同步元数据或默认库标记。复用既有拖动库与触感。普通版和 F-Droid 分别验证，保留 OneDrive 等版本差异。

## 验证

两版主包和测试包构建成功，各 3 项排序 JVM 检查通过；最终各 30／30 项 API35、x86_64 MuMu 设备方法通过。覆盖独立页进入／返回／锁定、错误密码留页和重试、保留原文件、key-only 既有创建、长按不误点、顺序写入和 Room 重开、12dp 对齐、大字号／多语言／深浅主题，以及忙碌和后台状态下空密码框仍显示且不可输入。原生 KDBX／MDBX 生命周期检查真实创建、验证、取消和移除，并核对独立兄弟库及原文件字节。

原生浏览入口的组件测试接收与 MainActivity 相同的 KEEPASS:36 标量导航请求，再由测试宿主展示浏览器；不是完整 Activity 导航测试。两版代表性新建页、磁贴和原生浏览截图已人工查看。截图、可编辑本地 M3E Canvas 和合成库仅留忽略目录与私有任务记录，未写入公开文档。

两版实际 R8 包均在隔离测试包名下，用与旧合成安装相同的 debug 签名覆盖升级；核对安装前后 UID、包名、x86_64 ABI、签名和 APK SHA。没有卸载或清数据。错误密码拒绝、原密码读旧记录、新记录写入及不同 PID 冷读、旧加密 ZIP 备份恢复均通过；恢复后新记录保留，临时 5 分钟锁定设置已恢复为立即锁定。此处不是用户生产签名安装的升级实测。

Debug 主构建普通版 219.904s／F-Droid 213.935s。最终测试构建普通版 167.130s／F-Droid 93.673s；主包未变化。R8 构建普通版 569.623s／F-Droid 765.847s。R8 期间有测试定位修正，原始 full-source 标记为 false；分别核对全部生产 app/src/main 和 kotpass/src/main 哈希与最终源码完全一致。最终测试构建 full-source 标记为 true；没有将中途测试源码变化隐去。
