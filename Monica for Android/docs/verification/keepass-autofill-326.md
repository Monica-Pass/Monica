# 原生 KeePass 自动填充修复：issue #179 / 未发布 1.0.326

普通版 versionCode 12；canonical F-Droid versionCode 33。修改与验证均使用合成数据；未操作报告者密码库。

## 问题与修复

主列表使用进程内原生 KeePass 展示源，自动填充却创建独立的 Room 仓库，搜索也只查 Room。真实合成 KDBX 基线中，主列表有 300 条而自动填充仓库为 0，原文件保持不变；这证明代码路径缺陷，不等于复现报告者手机的全部状态。

修复为自动填充认证后的请求范围原生读取，列表、搜索和空文件夹使用实际 KDBX 数据，不创建 Room 镜像、不解锁主应用会话。原生账号密码保持原值，不套用 Monica 密文前缀推断。目录显示解码，筛选仍用完整编码键；推荐项也遵守当前来源、数据库和文件夹筛选。

选择、详情复制、系统回调和延迟动作重新核对授权、锁库、原文件修订及进程身份。旧低 ID 回调遇到已注册 KeePass 镜像必须重新选择；不可读原库不能回退到旧镜像。屏幕关闭或已观察锁屏会永久撤销本批服务请求，独立保存任务不受此撤销影响。

本地“填充并绑定”仅修改绑定字段，保留未知字段、保护位、UUID、历史和附件；只读、修订冲突、取消和锁定拒绝写入。远端库及需要展开引用的绑定字段保守拒绝，普通读取仍支持。外部 provider 已接受输出后的取消不承诺零写入，沿用既有完成／恢复处理。原生填充后的可选 OTP 通知和自动复制暂不启用，显式 OTP 表单字段另行处理。
