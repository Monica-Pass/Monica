## Behavior and preservation

Authenticated account HTTP calls share session-bound refresh coordination. Concurrent verified 401s use one refresh and at most one explicit retry. IO failures and 503 Retry-After:0 do not replay writes; one-shot bodies also prevent OkHttp implicit body resubmission. Foreign signed transfers and the anonymous receiver do not inherit account credentials.

Attachment recovery seals the exact request identity and encrypted upload bytes before HTTP, stages the local queue before allocation, reconciles uncertain allocations, and prevents incomplete remote placeholders from replacing local pending files. Adoption commits each Room item before marking its recovery record adopted. Process and filesystem locks coordinate upload/reconciliation/cleanup. Account-key alias promotion retains the same vault/user/environment binding; a changed user or environment is rejected. The explicit stage/force-stop/resume pair verifies persisted ciphertext, lock rejection and duplicate-intent prevention. It is not a real cross-process server disconnect; ordinary HTTP-loss cases are separate tests.

Anonymous text/file Send reception uses native link review, None/Password/Email challenges, hidden-text reveal and verified file saving. The receiver uses the pinned official SDK protocol; email authentication depends on server support and is not supported by the inspected Vaultwarden revision. Counted access failures require an explicit retry. Closing, replacement, backgrounding and global lock revoke sensitive state. File-picker cancellation is exercised through Android's actual picker; cryptographic file-output checks use synthetic transport/output fixtures.

Personal account operations include exact hint readback, explicit hint clear/replacement, password changes, PBKDF2/Argon2id changes and server deletion. Preparation checks fresh identity, security stamp, KDF and the same original user key; password/KDF changes rewrap that key and do not rotate or reencrypt the vault contents. A durable sealed journal precedes dispatch. Unknown outcomes retire live credentials and freeze account traffic while retaining original local rows, queues, encrypted files and recovery material. Reauthentication requires the same original account/environment/key; failed journal cleanup remains retryable with the actual recorded phase. Confirmed server deletion keeps an original-password local copy; removing it is a separate action. New KDF choices are bounded; existing login parameters are not silently upgraded. Organization/Key Connector/new key formats are explicitly refused in this personal mutation path.
