## 反馈与参考边界

用户提供的分析 ZIP 对应 com.kongzue.secretinput 5.4.6.A（code76、target31）。Manifest 中声明 SYSTEM_ALERT_WINDOW；存在底部弹窗与新增项目布局。可见 Java 仅有资源表和加固壳，SIAutofillService 业务代码未解出；payload.zip 并非有效 ZIP。因此只能确认其具备悬浮窗能力和相关 UI，不能宣称已读到它的 onSaveRequest、确认窗口类型或复制了相同实现。生产中未引入此分析包代码。

## 实现

兼容开关默认关闭，关闭时维持系统 SaveCallback 的直接 Activity 启动；开启后先检查系统悬浮窗授权。设置页在未授权时显示“允许显示悬浮窗”，返回设置时刷新权限状态。没有授权时系统保存回调明确提示，不静默回退到已失败的直接启动。

授权后，onSaveRequest 通过应用上下文显示独立 TYPE_APPLICATION_OVERLAY 的 ComponentDialog/Compose 底部面板，然后结束系统回调。此时不启动 Activity、不枚举已有账号、不展示账号/密码/域名，也不写数据库。面板不依赖 AutofillService 的协程生命周期；仅点击“继续保存”才在窗口仍可见时发送明确目标、不可修改、单次的 PendingIntent，Android 14+ 为本次发送设置公开 BAL opt-in，随后关闭面板。原保存页执行身份验证、重复账号选择、保存目标和编辑提交。

窗口使用 FLAG_SECURE，跟随 Monica 的主题与自定义配色，内容可滚动。取消按钮/系统返回/点击外部、锁定代次变化、熄屏、关闭兼容或保存设置、新请求替换、60 秒超时均取消未使用令牌并释放窗口/订阅；进程死亡不恢复请求。身份验证、锁定、加密格式、密钥及恢复策略均未放宽。只新增固定 OVERLAY_* 阶段日志，不输出临时凭据或异常原文。

本地 M3E Canvas 在忽略目录 docs/design/hyperos-save-sheet-323，已确认实际加载的草图包含保存标题、说明、继续/取消按钮。6 个文案键覆盖 14 资源配置（13 语言），两版共用文件同步；Manifest 各自增量加入可选 SYSTEM_ALERT_WINDOW，保留渠道差异。

### 失败与修正记录

最早构建因权限组件被误插入点击回调而失败，已移到Composable内容中。随后两版并行大编译出现Kotlin堆频繁Full GC，主动中断并改串行；最终构建通过。没有把这些构建失败当成设备问题。

普通版最早面板套件3/5：一项表单等待期间出现测试IME生命周期异常，另一项在熄屏广播尚未送达时检查令牌。夹具改为开表单前选Gboard、熄屏等待实际广播。最新套件首项仍在打开表单前超时，同包单项通过；该剩余启动时序原因未确认，不把首次失败归结为同一个原因或宣称全部消除。旧日志和最终结果都保留。

首轮跨步骤保存卡在第二步inline候选等待，独立复测同样失败。第二步确有PASSWORD_STEP和成功填充回调，但硬件键盘条件下Gboard候选表面隐藏。保存回归改为等待实际第二步回调并输入新密码，仍检查真实系统保存和最终数据库更新；同时仅在IME可见时按Back，避免关闭表单。两版开启/关闭最终各两项框架保存均通过；这不把候选隐藏问题计为已经修复。

最早设置截图未包含下方授权按钮，已加强夹具并重跑两版中英文。普通英文设置用例结束前F-Droid安装阶段已开始，该次设置用例通过；没有把它当作并发隔离验证。F-Droid冷进程驱动首次遇到am kill已先结束目标、后续kill报告unknown pid，未进入表单；驱动改为确认目标已消失后再继续，随后完整通过。生产代码未因这些夹具问题放宽安全规则。

## 实际限制

没有故障 HyperOS 1 真机，Android 模拟器通过不等于该 ROM 已修复。某些 ROM 仍可能对悬浮窗或后台弹出界面另设限制。本方案要求用户主动授予系统悬浮窗权限；不使用 root/Shizuku、不自动切键盘。分析包不足以证明竞品恰好采用此实现。

本轮构建与设备验证使用Debug主程序/测试包，没有另做R8 Release。普通版现有seq94 Release不含本轮悬浮面板及此前键盘触感修改，不能把该旧包当作本轮结果。冷进程API32到编辑页、API35到身份验证的范围分别列明，不把准备设置用例计入功能回归数量。

本轮沿用此前已完成的酷安官方 HTTPS 原表单验证；中转入口另用系统 AutofillManager 和合成表单验证，不登录真实账号、不提交酷安账号数据。模拟器上的原网页通过不等于加固酷安 App 内或故障机验证。
