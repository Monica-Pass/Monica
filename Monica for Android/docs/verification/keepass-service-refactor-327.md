# KeePass service tree extraction — 1.0.327

2026-11-10，普通版与 canonical F-Droid 在各自 main 完成第一阶段职责拆分；未发布、未提交或推送，没有 APK 交付。

## 改动与维护边界

`KeePassKdbxService.kt` 从 10,287 行降至 9,508 行。本次搬出 33 个函数及一个私有 inline 辅助函数，形成三个模块内可见组件，没有新增 Gradle 模块或依赖：

| 文件 | 行数 | 职责 |
| --- | ---: | --- |
| `keepass/KeePassTreeNavigation.kt` | 263 | 遍历、UUID/路径查询、回收状态与恢复目标查询 |
| `keepass/KeePassTreeEditor.kt` | 313 | 已加载树的目录增删改移和条目替换；复用原 StringResolver 和 NativeMutation 实例 |
| `keepass/KeePassNativeSnapshotBuilder.kt` | 262 | 原生条目/整组变更快照，以及历史引用的附件和图标资源池 |

三个组件不持有数据库会话、密钥、DAO、文件写入或投影缓存。编辑器沿用原始 UUID/时间生成时机；快照构造沿用原 ChangeSet 创建时机。服务继续拥有锁、认证、缓存、来源修订检查、事务/保存与远端编排。KDF、加密算法、文件和变更集格式均未修改。

没有统一原有重复 UUID/path 的不同规则：条目查找取首项、目录索引保留末项、同路径条目集合合并全部、UUID 替换保留全部匹配。回收目录仍只依据元数据 UUID。未知字段、保护位、历史、原始压缩资源、缺失资源拒绝及遍历顺序保持原实现。

这只是第一阶段。服务仍含凭据、保存、同步和条目兼容转换；后者涉及 Passkey 密钥及照片 I/O，后续应独立定义边界和验证，不能当作无副作用 mapper 整块搬走。
