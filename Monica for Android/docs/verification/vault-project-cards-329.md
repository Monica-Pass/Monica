# 密码库页面多密码项目入口修复（329）

2026-11-19。普通版与 canonical F-Droid 未发布 1.0.329，分别保留 code 12 / 36。

## 结论与原始对照

用户在 328 的密码库页面观察到两个相似入口，点击任意一个都显示同一组多密码。上一轮只覆盖密码列表的分组和卡片渲染，没有覆盖独立的 VaultV2Pane 页面。本轮以已经包含上一轮修复的源码为负向基线，实际打开完整密码库页面后仍复现。

真实编辑器创建一个两密码项目，内存 Room 核验两条加密密码记录、一个项目标识；普通智能/自动模式、始终展开大字号、概览进入列表三个场景均显示两张卡片。逐个点击两张卡片后，真实 PasswordDetailScreen 都显示记录 1、2 的密码行，返回后两张卡片仍在。3/3 因“一项目一个入口”断言失败，runner 12.892 秒，完整回执保留在 `vault-project-cards-329-red-device.txt`。

这是列表把密码行直接当成项目入口造成的确定性显示问题，本次复现未写入第二个项目。数据模型本来就是每条密码一行、共享 `password_group_id`；不能通过删除其中一条密码来消除重复入口。

## 修复范围

- 新增 VaultV2PasswordProjects，复用现有包含来源的项目身份；标题、账号或密码相同的独立项目不会合并，原生 API Token 保留独立身份。
- 密码库普通/层级列表先执行原有逐行筛选、搜索和排序，再按项目显示一个入口。底层完整行集保留，第二条密码上的账号或附件筛选仍能找到该项目，节标题和滚动索引按实际显示项目计算。
- 选择入口时从当前可用行集中展开同项目成员，交给原有收藏、移动计划和软删除流程。选择一个项目显示一个选择项，操作包含全部密码，来源边界保持。未修改 ViewModel、DAO、加密、认证或存储格式。
- 概览数量、最近、收藏和常用入口按项目展示；原始行继续参与既有排名，第二条密码的固定项和使用记录保留。概览搜索/固定项选择器保留原始成员，再按项目整理准备好的搜索行；搜索文本仍只取既有允许的标题、账号、网站、应用等字段，不新增密码、备注等敏感搜索内容。
- 继承前一轮密码列表修复；本轮新增 8 个共享源码/测试路径逐字节同步两版。此前 7 个路径保留。

## 失败与复测边界

1. `red01` 构建成功，3 项设备方法全部按重复显示断言失败，是有效负向对照。
2. `main01` 主/测试 APK 生成，扩展 JVM 123/124 通过。已有 `VaultV2SecurityWiringGuardTest` 第 36 行要求页面内仍出现直接 `unlockVaultWithPassword` 的旧代码文本；任务开始时的原始页面也没有该文本。原测试和生产安全逻辑均未修改，后续专项构建不重复执行该类的两个方法。这一既有失败仍保留，不能把整个扩展检查称为全绿。
3. `main02` 123 项专项 JVM 全过，设备 18/19 通过、48.735 秒。操作测试的独立对照从目标项目复制时只清除了新项目字段，仍带旧 `replicaGroupId`，按现有兼容规则仍是原项目成员；排序后其标题代表了该项目，导致等待旧标题超时。只修正合成夹具，清除新旧两种身份并在打开页面前断言恰好两个项目；不改生产代码，不加超时，不删行为断言。随后普通最终 19/19 通过。F-Droid 首次设备批次使用修正夹具。
4. 所有前序日志和 XML 保留。前序 APK 没有另存副本，后续构建覆盖其输出文件，保留各自实际构建/安装 SHA，不能声称旧产物仍可直接安装。
