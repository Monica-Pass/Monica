# Bitwarden 完整密文文档与更新确认验收（1.0.325，未发布）

本批完成同一套文档层在普通版与 canonical F-Droid 中的保留、更新与确认。组织／集合扩展和高级认证依用户要求暂缓；既有组织解密、归属、条目密钥、集合与只读保护仍回归。完整客户端总清单尚未完成，本记录不能代替历史浏览／删除／清空与离线多次捕获、新类型与新加密格式、剩余同步、Send 和交换能力的验收。

## 行为与边界

同步及更新响应先读取有界原始 JSON，再转换 DTO；重复键（包括转义后的重复名称）与已知字段的大小写冲突均拒绝。更新从完整来源合并已知修改，保留未知顶层／嵌套字段、历史、FIDO、附件、归属和条目密钥，重复网址及自定义字段按身份与 occurrence 关联；无法安全关联未知数据则保留待同步修改。blob、partialData、encryptedByKeyId 及不支持的新类型不进入普通可编辑投影，既有条目不被替换为空值。此门禁不代表已支持这些新格式。

普通编辑保留原归档状态；明确登录／SSH 归档意图沿用既有 PasswordArchiveSyncMeta，未新增安全条目的归档 UI。HTTP 成功后还需完整字段确认才能退休 dirty／归档意图：已知 nullable 字段允许缺失与 null 等价、已知日期允许同一时间的不同表达；未知字段内容／大小写及数组次序保持一致。附件下载 URL 和格式化大小可刷新，ID、密钥、加密名称、大小及未知元数据必须保留。id／revision 由原调用链另行核验。丢字段、失败或会话撤销时保留原修订、来源和待同步状态；服务器已接受但回包不完整的结果可能进入原冲突流程，不承诺自动重试覆盖远端。

Room 80→81 仅新增 bitwarden_cipher_sources 表。完整来源与现有投影／上传确认在同一事务保存，账号、vault、cipher、revision 绑定在密封 envelope 内；保留最新观察与仍被本地编辑引用的原修订。缓存读检查全局锁代及当前 vault 会话，缓存不授权网络修改。来源快照复用 SecurityManager：配置主密码时需要 MDK，未配置主密码的旧安装沿现有兼容加密；这只适用于可重建密文快照。未在本批新增历史 pending intent 或长期明文／vault key 缓存。
