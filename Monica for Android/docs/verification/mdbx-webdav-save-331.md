# MDBX 自动填充保存与 WebDAV 请求修复（1.0.331）

## 范围与根因

330 用户报告 WebDAV MDBX 无法保存。本轮用包含同一保存逻辑的修前 331 构建复现，不能据此称使用过实际 330 安装包。自动填充独立认证后主应用仍处于锁定状态，而原生编辑器只接受主 Activity 的解锁及前台状态，真实保存入口抛出 `MDBX editor session expired`，尚未进行云端请求。修复此处后，真实选择器测试又发现新建记录使用原生 UUID，但保存后的回填只接受旧逻辑 ID，导致已经保存却不能返回 Dataset。

原生编辑器现在允许自动填充提供请求级认证回调。普通编辑仍沿用主会话前台与解锁条件；两种路径均保留编辑 epoch、全局锁代、密钥读取代、来源、原生修订与未知字段保护。保存页进入后台、关闭、替换请求或锁定后撤销授权。新建后按原生 UUID 或已验证旧逻辑身份解析精确对象，重新检查原生内容、修订及 Room owner，拒绝按标题或账号猜测。

## WebDAV 边界

- 已知目录的新文件条件上传从 PROPFIND + PUT + PROPFIND 减为 PROPFIND + PUT。目录创建/核验、历史枚举及连接检查仍可能额外请求，不能把整个同步称为两次请求。
- 保留上传前存在与 ETag 检查，已存在的 CREATE_ONLY 对象读取比较实际字节，实现上传响应丢失后的安全重试；拒绝已知同名不同内容及旧 ETag。PUT 同时保留 If-None-Match / If-Match，服务端返回冲突后再核对内容。坚果云实测忽略 If-None-Match，故不能只依赖该创建条件头；本轮对过期 If-Match 的探针实际得到 412 且原字节保留。未承诺不支持创建条件的服务端具有跨客户端原子创建保证。
- 成功使用响应 ETag；服务器未提供时不编造版本。移除上传后非必要查询，避免 PUT 已成功却因随后 PROPFIND 的 429 报失败。
- 一次 transport 的各文件共用最多两次重试、累计 30 秒等待预算。保留 host 级 backoff，遵守 Retry-After；取消时不再启动下一操作。未修改原生协议、历史发现或 checkpoint 配对。

## 验证方法

所有数据库、密码、备份及远端内容均为本任务合成夹具。MuMu API 35 / x86_64，专用次级用户；普通和 canonical F-Droid 分别测试。真实坚果云凭据仅通过私有临时配置供 instrumentation 读取，不进入源码、runner 参数或本报告。

保存页测试直接操作实际透明保存 Activity 和 V2 选择器，覆盖独立认证新增、更新、Dataset 内容、同名同账号诱饵、错误密码、取消、主动锁定和后台撤销。保存先标记待上传，不把本地保存等同于云端已完成；本轮未声称 WorkManager 自动调度在真实账号下端到端验收。新数据另用冷开的原生 MDBX 读取，不能只检查 Room 或 Toast。真实云模式额外发布 bootstrap，经 UI 保存后显式调用生产同步协调器上传增量，由另一份原生库及独立设备标识接收，核对实际字段并再次同步。

JVM 61 项/版包括 HTTP 请求序列、429/503/Retry-After、响应丢失同字节重试、冲突、共享预算、取消、协调器历史/失败恢复及自动填充读取。F-Droid 仅在测试中为本机 MockWebServer 开启 HTTP 并于 teardown 还原，生产 HTTP 策略不变。

## 失败记录与限制

修前真实 UI 保存及 HTTP 请求预算用例失败证据保留。第一版修复中 picker 保存但回填失败，定位后补原生 UUID 解析。后台测试的 Activity 已销毁且未写入，但测试父 task 在后台导致 result 回调超时；夹具重新聚焦自己的 task 后保留原取消/无写入断言。F-Droid 首轮新增 HTTP 用例被其明文 HTTP 保护拦住，随后只修改测试前提。

真实坚果云首轮拒绝过长顶层测试目录，未进入保存；下一轮保存/上传/独立接收通过，但顶层同步目录 DELETE 返回 403 OperationNotAllowed，使测试在清理步骤失败。后续复用该专属目录下的短子目录，顶层目录内的初次合成文件已精确删除。上述失败不算整批通过，原日志完整保留。

设备结果只代表合成 API35/x86_64；不覆盖用户原库、物理手机/OEM、ARM64或所有云服务。限流故障由确定性 HTTP 服务模拟，未故意向坚果云制造高频流量。Release 升级使用同包同签的修前与修后实际 R8 构建；不是实际 330 包升级证明。未更改库格式/加密/KDF，未提交、推送、发布或交付安装包。

真实服务端条件探针发现坚果云忽略 If-None-Match: *，返回 204 并覆盖专属合成探针内容（随后已删除）。早期省去上传前查询的实现因此撤回，最终保留原来的前置检查，只移除上传后查询；早期 3→1 请求测试通过不作为最终方案结论。补充模拟不支持条件头的服务器，以及查询后发生创建竞争的用例。

## 保留数据 Release 升级

两版均先在修前实际 R8 Release 中经真实界面设置主密码、创建本地密码记录并导出加密 ZIP，再创建内部 Sky MDBX 及原生记录。随后只用同包名、同签名的新 R8 包覆盖安装，未卸载或清应用数据。原主密码解锁、错误密码拒绝、旧本地记录显示、新记录写入及不同 PID 冷启动读取通过；删除自有旧合成记录后，从旧加密备份恢复，核对旧记录密码及新记录仍在。备份往返临时使用 5 分钟自动锁定，最后恢复立即锁定并重新登录。

实际系统自动填充入口及云端流程用 Debug instrumentation 单独验证；R8 升级验证使用真实主界面和内部 MDBX，不等同于实际用户云库升级、真实 330 包或所有 R8 系统入口验收。测试包名隔离、测试签名一致，最终 APK 哈希及 ABI 已从设备安装路径重新核验。

两版原生 MDBX 旧记录均通过升级后显示原密码、真实编辑页修改密码并保存、再次不同 PID 冷启动后读取新值；保持同一旧记录及原库。对应 `release-main-native.json` / `release-fd-native.json` 回执记录了实际进程变化。
