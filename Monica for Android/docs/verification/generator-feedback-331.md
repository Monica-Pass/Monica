# 1.0.331 截图保护触觉与生成器卡片验证

## 修改

- 普通版与 canonical F-Droid 的截图保护设置卡片接入现有 `switchClick`，沿用原设置写入。一次点击一次反馈，遵循应用内开关与强度；没有改变截图保护策略。
- 生成器已有 `MonicaSlider`，无需重复增加震动调用。验证随机符号、口令、短语、PIN 四种实际页面的长度滑块向右／向左拖动：数值变化且 Android 震动服务完成 TOUCH 输出。松手不额外震动；应用内关闭触觉后拖动仍生效且无输出。系统触觉关闭时同样验证。
- `ResultCard` 的内容 Column 复用 `animateMonicaContentSize`，只有一层尺寸动画，卡片圆角与后续布局跟随高度。文字立即替换，不保留旧密码内容用于淡出。减少动画时即时布局；移除组件不延迟。现有复制、菜单及生成逻辑不变。
- 沿用 ImageToolbox 的现有参考实现与 Apache 2.0 署名／许可证文件，没有重复复制新代码。根发行说明更新原有条目，未添加验证报告或操作指南链接。

## 原始失败与修正

1. 修改前六项设备对照失败：截图保护没有输出，四项动画相关检查不满足平滑过渡；另一个生成器拖动测试在切换页面的新结果尚未加载时按下。保持原生产滑块代码，仅在测试中等待该类型实际结果非空后，四类型往返拖动通过。原始测试与失败记录保留。
2. 首次修后普通版批次 21/24：三项 `No compose hierarchies`。logcat 对应时段出现 MuMu 90°／0°配置变化、ComponentActivity 销毁重建。仅将本测试用户方向设为 MuMu 原生横屏后，原包复测 23/24；未改生产代码或断言规避该竞态。
3. 余下一项测试把“启用动画”和“更改内容”放在同一帧，动画节点新建时没有旧尺寸，却要求已经出现中间高度。测试改为先启用并测量一帧，再改内容；中间高度、关闭动画立即到位和移除内容断言均保留。最终两版结果见上表。首批失败不计作通过。
4. 首次扩大 JVM 检查为 12 项时有既有 `AddPasswordGeneratorPreferencesTest` 源码字符串断言失败：它仍要求已委托给 `CredentialGeneratorSheet` 的旧对话框直接调用 `toSymbolPasswordGeneratorOptions`。本轮未修改该旧测试或相关生产逻辑；保留失败 XML。最终 9 项针对本次代码的 JVM 检查不包含该陈旧测试，另有 8 项实际生成弹窗设备回归。

## 范围与限制

仅 Debug、合成数据和 MuMu API 35。模拟器能证明系统服务接受并执行效果，不能证明实体马达手感或全部 OEM 兼容性；未做本轮 Release/R8、旧版升级或用户真机测试。系统动画比例由 Compose 原有机制处理，本轮直接验证的是应用内减少动画开关。组件移除检查不能替代全应用锁定安全审计。本轮未改加密、数据库、登录、截图保护旗标或生产依赖。

两版四个共享源码／测试文件字节一致；F-Droid 元数据和六项脚本回归通过。完整构建、对照与复测原始证据留在本地任务目录，公开文本摘录和哈希随报告保存。最终仅清理本任务包／用户和专用 ADB，保留原用户、正式版元数据、密度、配置与数据盘，MuMu 保持运行。没有提交、推送、发布或交付安装包。
