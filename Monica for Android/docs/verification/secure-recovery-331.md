# 恢复保护 1.0.331 验证记录

2026-11-23。普通版与 canonical F-Droid；普通 code 12、F-Droid code 38，仍为未发布开发版本。本次增加恢复材料分类、独立密码验证、设置入口及故障引导，沿用原恢复事务、加密格式和密钥策略。

用户报告为 329 / API 37 的 `MISSING_MASTER_KEY / PREFLIGHT`，停用 OMK 后恢复正常。这支持密钥访问路径变化的解释，不能据此断言原密钥或恢复文件被删除。下面全部为本机合成数据验证，不是该用户设备的修复确认。

## 对正常使用的保护

- 主应用密码认证成功并提交会话后，才尝试可选后台演练；演练结果不改变已成功登录。指纹、自动填充、独立输入法的原认证策略保留。
- 自动演练使用独立最低优先级单槽 worker，不占正常登录/自动填充的 worker、不排队多个密码；昂贵 KDF 在恢复文件锁外执行。15 秒、暂停或锁定撤销结果；同步底层调用不能保证立即终止，结束时清除临时字符和密钥数组。
- 自动演练只读已有材料。显式设置验证仅允许健康旧安装或允许重新登记的状态补齐材料，保留现代发布标记、防回滚、原文件及撤销状态；损坏材料不会被静默覆盖。
- 验证独立解密恢复密钥、配置快照和数据密钥，并检查当前配置、修订、选择器与会话。缓存只保存摘要/会话/时间，锁定或材料变化失效；设置验证不授予登录会话。
- 启动失败页按材料状态给出动作；缺失、损坏、撤销、未知版本不会显示无效恢复按钮。Monica 不申请 Root、不自动改变模块作用范围或清除数据。

后台工作仍有计算开销，本轮验证了线程隔离和正常功能，没有做所有真机的帧率、电量或负载基准，不承诺零开销。

每版汇总 120 个不同设备方法取得通过结果；不是整批全绿。完整方法清单、每批结果、构建与 APK 哈希见同目录 JSON。

- 正常登录、改密、后台输入清除、secondary 超时及多语言搜索 8 项每版通过；FD 与新增 17 项合批为 25/25。

- 安全回归两版各 77/78；唯一未通过项 `SecureStartupInstrumentedTest#existingUnreadableXmlIsNotTreatedAsANewInstallation` 期待 `EMPTY_OR_UNREADABLE_STORE`，实际 `UNREADABLE_SECURE_STORAGE`。原生产基线 APK 在同设备单独复现，不是本轮新增差异；未修改断言掩盖失败。

## 真实 OMK 与材料保留

使用现有 MuMu API 35 / x86_64 专用实例、第三方 OMK ba6f300。只临时追加本任务包/用户作用范围，不改 seed、keybox、不重装模块。实际 injector route 日志确认目标 UID 走 System/Omk。

Debug 两版均完成系统库创建 → 切入真实 OMK → 原密码与二次确认恢复 → 原密文保留 → 旧读/新写 → 新进程冷读写三阶段。Release 两版在升级后的同一库完成两个方向；每方向逐一验证缺失、损坏、撤销、未知版本的原因可见且无恢复按钮，随后恢复原材料，再验证错密码拒绝、取消保留、正确确认恢复、旧读、新写及冷读。

每次故障注入只修改自有合成安装的恢复文件，finally 还原原字节、所有者和权限。确认恢复后到再次正常登录前，原恢复 envelope 字节保持一致。材料/库/备份的私有归档只留本地，不写入公开结果。
