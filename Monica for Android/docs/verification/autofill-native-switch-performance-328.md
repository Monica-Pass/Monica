# 自动填充原生库切换性能：未发布 1.0.328

2026-11-17，普通版 code12 与 canonical F-Droid code35。用户确认等待发生在自动填充选择器切换到某个 KDBX/MDBX 库之后。本轮生产改动仅 `AutofillPasswordSource.kt` 与 `BoundedSecureDataRead.kt`，保留工作区其他既有改动。未提交、推送、发布或交付安装包。

## 原因与改动

MDBX 列表路径在逐条原生读取及转换过程中反复执行完整授权回调，包含安全配置和系统状态读取。300 条记录的完整外部授权回调达到 1,521 次；KDBX 为 319 次。KDBX 暖读取还复用已解锁解码数据，MDBX 每次经过开库、解锁和逐条受控原生披露，不能仅按格式名称比较引擎速度。

只在结果尚未发布的列表遍历中使用即时取消、source 撤销、全局锁代及 KDBX 逐库锁版本检查；读前、worker 前后、结果交付及列表发布边界仍完整核验。KDBX 有修订号的实际选中读取、MDBX 单条填写和钱包选中读取保留原完整校验。未改原生授权/约束、来源配置、原文件修订、KDF、算法、格式或缓存策略，也未增加持久明文。

## 合成性能结果

MuMu API35/x86_64，真实原生文件各 300 条；每轮新建请求 source，同一进程连续加载三次。单位毫秒，以下仅 `source.load`；建议排序准备另需约 27–103ms。未测真实用户设备，三次样本不构成固定提速承诺。

| 批次 | KDBX 第一次 / 后两次 | MDBX 第一次 / 后两次 | 完整检查 KDBX / MDBX |
| --- | --- | --- | --- |
| 普通修前 | 617 / 302 / 263 | 1779 / 1612 / 1446 | 319 / 1521 |
| 普通首次修后 | 339 / 70 / 46 | 583 / 384 / 421 | 14 / 12 |
| 普通最终版 | 631 / 95 / 89 | 1132 / 779 / 680 | 14 / 12 |
| F-Droid 最终版 | 331 / 54 / 43 | 578 / 359 / 364 | 14 / 12 |

普通最终设备批次与宿主 R8 构建重叠，MDBX 原生诊断读取也由约 373ms 升到 732ms，存在资源竞争，不能隐去这一结果。首次修后列表逻辑与最终相同，但最终进一步限制优化仅用于 KDBX 列表路径，恢复有修订号的动作路径完整检查。F-Droid 最终原生诊断约 335ms；KDBX 暖原生诊断约 21–32ms。诊断读取省略外部回调，只用于区分开销，非生产路径。尚未拆分 MDBX 开库/KDF 与逐条读取耗时，不宣称 KDF 是全部剩余瓶颈或 MDBX 已追平 KDBX。

## 失败与限制

- 两版本轮首次 R8 Picker 认证仍在点击后退出，锁代从 1 变 2，source 尚未建立；保留生命周期与 logcat。相同主 APK、相同探针、相同等待和断言第二次通过。此前版本已有同类记录，根因尚未确定，本轮没有修复此独立问题，不称首次整批通过。
- 最初 MDBX 性能夹具单次提交 299 条超过引擎 256 限制，仅将夹具拆为每批 200 条。首次失败保留，未放宽引擎限制。
- 本地 Release 驱动的 Python 导入路径曾误命中同名 Debug build.py，初次 upgrade/four/ui 调用仅多跑构建或报 FileExistsError，并未执行升级；修正驱动导入顺序后才进行本报告的实际升级。最终测试过的 Debug 主/测试包从设备拉回并逐一核对原测试 SHA，未以之后重建输出冒充同包。
- UI 驱动曾用错繁体入口文字、因人工步骤间隔触发正常锁定；uiautomator 多次在输出 XML 后以 139 退出，只接受当前新文件并核验完整 XML。普通 importB06 和 FD exportA03 的 135 输出保持失败，后续新快照继续已确认状态，不把工具退出当成产品崩溃或成功验收。
- 未使用真实用户库、真实云端、物理 OEM、其他 API/ABI 设备或全部规模/内容组合；没有承诺所有长等待均消失。未修改原生引擎，不以本测试作数据库格式性能排名。
