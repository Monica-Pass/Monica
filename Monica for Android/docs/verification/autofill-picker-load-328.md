# 1.0.328 自动填充选择器加载验证 — 普通版

所列合成场景验证及测试环境清理已完成。结果限定于以下环境和检查范围，未发布新版本或交付安装包。

LOCAL 模式先恢复来源设置，再读取所需数据；批量有效性校验减少重复授权检查，同时保留锁代、快照成员、取消和动作执行前的重新校验。新增页面的 ViewModel 延后到实际进入页面创建。测试发现的保存回调与返回回调互相撤销问题已用最小导航修正处理。

## 加载范围与上游参考

LOCAL 不再枚举或打开无关原生 KeePass 库，钱包在解码前按现有 ownership 规则筛选。旧包对照可复现 LOCAL 触达故意阻塞的原生库；最终相关设备测试验证该库零读取。550 条记录的逐条校验需要 550 次完整授权检查，批量路径实测为 2 次，循环仍检查身份和版本，动作执行时仍单独复核。

参考固定版本的 [Keyguard](https://github.com/AChep/keyguard-app/commit/d030b75228185b7f979f0e9ed987c8abbba12b9b) 与 [Bitwarden Android](https://github.com/bitwarden/android/commit/6366dd5b848eeef3206501d42040302ad0be1042)：借鉴共享列表准备、先筛选用途以及请求替换/取消后的结果校验；未对上游应用做同机跑分。Monica 已有 Rust 自动填充匹配器，本次减少匹配前的无关加载和重复检查，没有新增 Rust 实现或修改加密算法、KDF、存储格式。

## 实际验证

| 检查 | 结果 |
| --- | --- |
| JVM | 518 项、68 suite；最终无失败、错误或跳过 |
| Debug 设备 | 67 个不同方法通过：17 批量来源、9 实际 Picker UI、4 LOCAL 钱包、7 钱包回归、30 原生 KeePass |
| R8 构建 | 529.485 s；实际 APK/mapping 哈希与冻结记录一致 |
| R8 入口 | Picker 认证/取消、独立 :ime 解锁 Activity 认证/取消，共 4 项通过 |
| 保留数据 | 同签名合成包覆盖升级后，旧四条记录及原 ID/密文/分类保留、可解密 |
| 真实备份恢复 | UI 导出/导入第五条后，进程 22376 与冷进程 22507 验证成功；原四条保留 |

两版 67 方法集合相同，不把重跑次数相加。环境为 MuMu、Android API35、x86_64，全部使用自有合成记录。

## 有限性能样本

550 条新增 MDK 用户名记录、原四条记录及 14 张银行卡；三个独立冷进程经过真实密码界面，解锁到目标记录可见为 **1020/961/931 ms**。同一夹具旧 R8 为 1386/1465/1497 ms；样本中位数由 1465 变为 961 ms。新包测量期间主机还运行 F-Droid Gradle，不能据此给出通用提速百分比。计时起点在 instrumentation 初始化之后，不是点击应用图标到全部可用的总时长。用户视频约 11 秒的严重程度未在此环境同等复现。

## 数据与失败保留

实际 UI 显示恢复 1 条；没有据此推断完整跳过/失败统计。第五条写入是 SQL 配合生产 SecurityManager 加密，不是真实编辑器保存；编辑器证据来自 Debug 的真实 framework Dataset 测试。恢复若重分配 ID，先核验随机归属标识及内容，再登记该 ID。最后仅移除自有第五条；大夹具也仅按 manifest 删除 550 密码和 14 卡，四条旧记录保持可读。最终仅删除本任务两个测试用户，恢复原用户；精确清理 146 个已记录的 UI dump 路径，停止本任务启动的模拟器，保留数据盘和配置。

普通旧包负向对照 2/2 按预期失败；普通初批原生回归 28/30（一项缺通知权限、另一项重建后可见等待失败），同包诊断及最终完整批次后来通过，重建根因未独立修复。候选密码保存回归、Dataset SDK 编译失败、普通最终 JVM 首次 1/518 失败均保留。最后一项为 512 MB 测试 worker 的 63 MB 安全上限不足以运行 64 MB KDF 向量，仅任务 worker 改为 1 GB 后 518/518 通过，没有放宽生产 KDF 保护。UI 导航失败步骤也保留；单步点击或文件存在不作为恢复成功。首次清理脚本在删除测试用户后因主机 GBK 解码本地 JSON 失败；显式 UTF-8 收尾完成剩余清理并核对停止状态，原失败保留，不算应用故障。

## 边界与证据
