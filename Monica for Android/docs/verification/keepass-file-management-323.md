# KeePass 原库文件管理 1.0.323 验证

> 2026-10-31 后续交互纠正：本文的独立文件状态栏和选文件合并弹窗已由 `keepass-path-merge-323.md` 所述实现取代；下文保留为前序验证记录。

本轮覆盖普通版与 canonical F-Droid；普通版 versionCode 12、F-Droid 30，不发布。原始用户数据库只读保留，所有编辑使用隔离副本。公共 API32 AVD 复用；Release 与竞品交互使用本轮专用访客，未初始化或清理主用户数据库。

## 根因与实现

- 基线连续两次复现：本地重新加载误走远程同步，300 条旧记录仍保留；关闭回收站功能后，299 条旧回收条目混入正常列表。普通名称为 Trash 的分组不应被隐藏。
- 本地重新加载直接重读原文件；远程重新加载继续经过原有同步/冲突处理。回收成员按非零回收站 UUID 及其后代判断，独立于未来删除是否启用回收站。
- 选中且解锁的可见数据库在恢复前台及每 5 秒检查密文版本。未改变时不执行 KDF 或完整投影。已改变则载入文件并显示状态；旧编辑基线不随列表推进，避免覆盖外部删除。
- 重新加载先解码，再替换有效会话；失败保留最后有效数据与重试入口。替换检查缓存实例及锁定轮次，迟到结果不能重新打开已锁定库。空库加载也发布状态更新。
- 单库菜单新增保存、合并、重新加载；移除多余的手动 Wi-Fi 同步。现有整应用附近同步保留。合并弹窗展示选中文件名、密码及可选密钥文件，跟随主题。
- 新合并器按 UUID 同步，修改时间与移动时间独立处理；相同时间的不同条目内容保留当前版本，将另一版放入历史。删除墓碑作用于后代，较新修改/移动可保留；附件池、条目历史与自定义图标保留。歧义 UUID、树循环、不能判定先后的插件数据冲突及附件表示冲突拒绝写入。写入前创建恢复副本，沿用原验证写入和冲突保护。
- 列表首次读取失败不会结束订阅，解锁或显式重新加载后可继续显示；订阅同时观察单库锁定轮次，不主动解锁。
- 现有跨库复制、移动、关联副本路径保持独立；不把新文件合并当作复制导入使用。

## Release 与竞品实测

使用官方 KeePassDX 4.5.6 libre、KeePass2Android 1.15-r6 x64，以及本地 R8/resource-shrunk Monica Release。Monica Release 仅以与公共安装匹配的本地测试证书重签，包标志不含 DEBUGGABLE；不是应用市场发行签名。

用户提供的原始副本是 KDBX 4.0 / Argon2：0 条有效记录、0 条回收记录、2 个分组、624 条删除记录。两款竞品均打开为空库。

从此副本构造 3 条正常记录、2 条嵌套回收记录的合成库，通过系统 SAF 选择同一份可写文件：

1. Monica Release 正常列表显示 3 条，排除 2 条回收内容；实际“保存数据”成功。
2. KeePass2Android 修改名称并保存；系统任务切回 Monica 原 Activity，自动显示新名称和外部更改状态，进程保持不变。
3. KeePassDX 将 3 条移入回收站；切回 Monica 原 Activity 后正常列表自动变空，显示外部更改状态，进程保持不变。
4. KeePassDX 清空回收站；Monica 合并删除前的旧副本仍为 0 条。独立解码确认 630 条墓碑，旧条目未复活。
5. 合并含受保护自定义字段、附件与历史的新条目。独立解码确认 1 条记录、1 份历史、1 个附件、630 条墓碑，字段空格与附件字节保留，仍使用 Argon2。KeePassDX 与 KeePass2Android 均已重新打开此结果。

初次竞品操作时间超过默认自动锁定，单独记录为锁定后重入；后续将专用访客的自动锁定调整为 1 小时，使用系统 task focus 回到原 Activity 完成以上进程不变检查。访客设置随访客清理，不改主用户设置。

设备回归包括外部重载/订阅恢复 12 项、Monica 原生 UI 13 项、KDBX 兼容性 15 项、冲突/合并 10 项、真实编辑页 1 项和删除界面 1 项。JVM 为新合并器 15 项、跨库转移 7 项、所有权 2 项、TOTP 跨库绑定 4 项。F-Droid 的 28 项在前序完整构建运行；最后仅调整列表订阅与错误显示，相关行为由最终 52 项设备测试覆盖，未重复编译运行未变化的 JVM 套件。

高度动画前的 R8 Release 验证四次进程冷启动/解锁，均直接显示已有合成条目，不切换筛选器。将本轮合成源文件临时改为只读后，真实点击“保存数据”：错误弹窗可见，关闭弹窗后错误状态仍在，文件哈希不变；恢复权限、重新进入数据库后保存成功。前序 Release 另验证损坏外部文件时保留已载入条目与重新加载入口，恢复文件后错误清除；合并弹窗显示所选文件名。

收尾实测曾发现两个问题，均修正后重新构建验证：缓存失效隐藏保存错误；进程冷启动先于解锁订阅时，初始读取异常使列表订阅结束，切换数据库才能恢复。后一问题有实际 Release 日志和独立文件解码证据，新设备回归覆盖锁定时订阅、解锁后同订阅恢复、单库锁定立即隐藏且不自动解锁、初始坏文件恢复后继续接收数据。写失败导致会话失效时，需要重新进入数据库恢复，仍是当前体验限制。

完整竞品交互在本轮前序 R8 Release 上执行；高度动画前的最后一个 Release 补充上述冷启动/保存失败检查，没有把前序竞品操作称作全部重新执行。28 个共享生产/资源/测试文件哈希一致，两版 scoped diff-check 通过。证据见同目录 keepass-file-management-323-evidence.json；保留基线两项失败的负向复现与最终设备日志。

## 状态栏高度过渡

用户截图中的错误状态含额外按钮，行高比成功状态更高。KDBX 状态容器改为 260ms 缓入缓出的尺寸过渡，文字换行、按钮出现/消失时带动下方列表连续移动；面包屑已有重复的两层尺寸动画改为由外层独立控制，密码库在路径与批量状态之间也保留同一高度容器。系统关闭动画时遵循 Compose 动画时长缩放；没有给锁定隐藏添加退出动画。

动画最终验证：两版追加 Debug 主程序构建通过，普通版同时重新完成 R8 Release 构建；数据功能未再改变，沿用前述各 52 项设备/28 项 JVM 回归。普通版最终 R8 Release 在专用访客正常字号和系统 1.5 倍字号下录制“外部损坏→保留条目与失败状态→恢复→重新加载”流程。动画前录屏没有中间高度；最终两种字号均出现多个展开、收缩中间高度，列表随状态栏移动（视频压缩边界检测容差 8px），恢复后原合成文件字节一致。视频采用可变帧率，未据此声称精确实测 260ms、性能基准或全场景无掉帧；260ms 为代码设定。检查了最终原生截图，大字号能完整显示换行文案与操作。临时字体设置已恢复，系统关动画/密码库批量状态切换只完成代码检查，没有冒称录屏覆盖。

一次临时切换 Debug 包后的界面探针观察到安全存储保护页，尚未完成动画场景便停止；原因未确认，未清理数据或修改密钥策略。恢复前序 Release 后正常解锁，最终 Release 也完成上述两轮真实流程，该 Debug 尝试不计为通过。界面驱动首次连接过早曾返回空响应，重新连接后正常。首轮视频解码默认重采样可变帧率，丢弃了中间帧而使探针失败；改为保留每个编码帧后，同一最终视频与基线对照均通过，未为此修改生产逻辑。

## 与原生编辑器的剩余差距

- 外部变化提示目前针对可见解锁库、每 5 秒检查文件；云提供商的后台变化通知与可靠实时订阅未完成。WebDAV/OneDrive 仍遵循既有同步语义；F-Droid 不增加 OneDrive。
- 用户文件从系统文件管理器直接 ACTION_VIEW 打开 Monica 的通用入口仍不足；目前走应用内“打开”选择器，部分旧文案仍使用“导入”。
- KDBX 硬件 challenge-response 解锁未接入；物理 Passkey 功能不能替代该能力。
- 保存仍包含原库编码、KDF 与提交校验；本轮不提供可信的速度胜出结论。构建期间的交互耗时不能作为基准，实际手机、较大数据库及不同云/SAF 提供商需单独测试。
- 新合并器尚未达到 KeePass 桌面多年互操作覆盖：更多第三方/插件字段、历史 KDBX 变体、密钥变更以及复杂多端并发需要扩展语料。现有 Kotpass 数据模型以外的任意 XML 扩展不能宣称全部无损。
- 状态栏、错误和合并流程仍有进一步细化空间，例如同时间的分组属性冲突明细与更直观的变更预览。

测试夹具问题：最初 Debug AndroidJUnitRunner 依赖被 R8 优化的 Kotlin 类，不能直接运行于 Release；改用独立纯 Java 界面驱动。截图保护仅在专用访客内关闭。若干界面探针在过渡帧过早取值；合并成功文字首次断言误写成 Data merged and saved，实际资源为 Data merged，已更正夹具。上述不计作生产功能失败或已通过的最终回归。

## 清理与原始文件

结束时再次确认原始文件 SHA-256 与开始时一致（13,113 字节）。停止本轮界面驱动并移除转发端口，核对专用访客名称后移除该访客，返回主用户；保留其他三个既有测试用户和公共 AVD。仅清理本轮明确命名的临时文件、旧固定夹具及两版合成编辑截图，没有清除主用户应用数据。当前普通版保留最终 R8 Release 安装，F-Droid 保留最终 Debug 安装；不交付安装包，不提交、推送或发布。
