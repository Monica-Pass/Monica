# 登机牌原码与 M3E 出示码入口验证

日期：2026-10-30。两版均为 1.0.323 未发布；普通版 versionCode 12，canonical F-Droid versionCode 30。

## 实现与交互

- 扫描时保留完整 IATA BCBP 文本和原始码制，包括固定宽度空格、尾部空格、多航段及扩展内容。PDF417、Aztec、QR 和 Data Matrix 按保存的码制重新编码显示，生成的模块排列可以与原图不同，文本和码制不变。
- 原码与可编辑行程字段分开保存。修改航班、乘客或座位不改变原码，出示页上的航线与旅客标签取自原码。
- 编辑页支持重扫和移除，均在用户点击普通保存按钮后写入；草稿重建状态中的原码使用既有加密接口保存。旧票证没有原码时，引导用户编辑并重新扫描。
- 会员码、积分卡码、登机码和扫描入口使用统一 M3E 28 dp 大圆角操作区，跟随应用主题及自定义配色，包含图标、主次文字、方向箭头和整行触摸反馈。
- 出示页提供独立黑白扫码区域、整数倍像素缩放与静区；竖屏放大宽条码时转向使用屏幕长边，横屏将资料放在侧边。未知码制或不可显示内容保留数据并显示本地化提示。
- 应用整体锁定或来源 KDBX 锁定后关闭出示页；解锁不会自动重新打开。窗口继承原应用截图策略，生产逻辑不将条码图片写到磁盘。

## 存储与兼容

- `DocumentData.boardingPassBarcode` 为有默认值的可选字段，无 Room 表结构迁移；旧文档可读，未知格式字符串往返保留。
- 本地、KDBX、MDBX 使用既有完整文档序列化及加密路径。KDBX 的完整 Monica 数据字段沿用受保护的 `EntryValue.Encrypted`。
- Bitwarden 使用加密且隐藏的 `monica_boarding_pass` 保留字段；缺少字段保留已有原码，明确空值才移除。损坏 JSON 或无法解密的数据在覆盖本地记录前失败；错误信息不包含输入原文。
- 原码未加入普通可搜索钱包字段或自定义字段列表。跨库回归覆盖本地、KDBX、MDBX 多目标保存及实际重新打开，并覆盖 Bitwarden 加密上传、全新下载、缺字段保留、明确移除及损坏数据拒绝；Bitwarden 使用本地协议夹具，未连接真实账户。
- 此次不改变已有跨库目标选择、所有权规则、KDF 或密钥恢复策略。

## 中途失败与修正

- 首次设备运行时，PowerShell 将原生图形诊断 stderr 视为终止异常，导致 adb instrumentation 客户端断开，随后出现 UiAutomation 连接失败。已改用 Python 子进程合并捕获输出；当时 Activity 服务仍健康，没有据此认定系统崩溃或生产缺陷，也没有重启/清空模拟器。
- 下一轮 37 项中 35 项通过：两个夹具分别错误预期损坏远端码返回 Error（实际抛出安全异常），以及因扫码提示同时出现在背景操作区与弹窗而匹配到两个节点。夹具已按实际拒绝契约及弹窗作用域修正，最终完整回归结果如上。
- 原生截图检查发现原先竖屏放大只隐藏资料而未增大 PDF417，且白色区域留空过多。已改为利用长边放大，并加入实际黑色码区尺寸变大的断言，保留显示后解码一致性验证。
- 加入白色区域高度上限后的设备回归暴露了生产布局问题：加载指示器和图片占用高度不同，尺寸变化又重置图片，形成循环。该轮因 `ComposeNotIdleException` 失败并提前停止；将区域改为受可用空间约束的固定高度后，重新构建并执行完整回归。没有放宽空闲等待或删除显示断言。
- 提前停止时留下一个本轮唯一 UUID 的合成 KDBX 登记和四个临时文件；清理前确认没有密码、卡包、Passkey、分类或待提交记录引用它，MDBX 临时文件未登记且创建时间属于该测试窗口。仅删除该登记和核实的文件，事务内确认其余表行数不变。辅助检查最初将 MDBX 的 `file_path` 列误写为 `filePath`，只读查询失败后修正；未因此修改应用代码或表结构。清理证据见 `boarding-pass-code-323-owned-fixture-cleanup.txt`。
- 最后补齐既有会员出示入口的全部语言后，普通版额外执行资源重打包；以本记录的最终 APK 资源审核为准。
