## 已确认问题与修复

- 完整传统 AES-CBC-HMAC 条目携带 `encryptedByKeyId` 时被旧门禁跳过。现核验官方 SDK RFC9679 COSE 对称密钥 thumbprint 的前16字节，确认其指向当前账号或组织的包装父密钥，再沿原链解开独立条目密钥。公开向量 `ac4ecffb2e087a59180d1dd19950b8e9`。不查找任意缓存密钥或回退错误密钥。
- 真实服务器把缺省/空自定义字段规范化为 `[]`，并从现代第一条 URI 更新旧 `login.uri`，造成已上传修改未退休、虚假冲突。只规范化已知空字段等价及派生主网址；保留全部 URI、匹配规则、校验字段和未知数据的严格确认。
- 坏备注密文曾被降为空值，覆盖原备注、更新修订和完整源，仍返回成功。现在投影及源提交前验证所有已知密文字段，覆盖五类条目、网址、校验值、可识别的加密自定义字段与 Passkey 元数据、历史密码及附件名；保留既有明文扩展兼容。失败保留最后可读副本和原修订。
- 文件夹名称及 Send 名称、备注、文本读取失败曾替换原数据并返回成功。现在保留原数据，文件夹/Send/附件对齐失败计入同步不完整，取消透传；错误不更新成功同步时间。Send 临时密钥在映射完成或失败时清除。

完整加密源继续保留历史、附件、归属、权限、归档及未知字段。真正的 partial/blob 或未实现的新算法明确报告失败并保留源，不能宣称已支持显示或编辑这些格式。权限禁止读取的组织条目遵循原安全边界。
