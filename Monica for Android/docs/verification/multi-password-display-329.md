# 多密码项目重复卡片修复验证（1.0.329）

日期：2026-11-19。普通版与 canonical F-Droid 的未发布 1.0.329 已同步修复；普通版 code 12、F-Droid code 36 保持不变。

## 问题与修复

一个显式项目包含两条密码时，“始终展开”模式和 `CategoryFilter.LocalOnly`（仅本地）会把两条密码行显示成两张相同项目卡片。两张卡片打开的是同一组记录；本次复现中数据库没有多出第二个项目。普通 Monica 本地视图配合自动模式原本显示正常。

修复同时覆盖分组、原生结果解码和卡片渲染：

- `PasswordProjectCards.kt` 按现有 `passwordProjectKey()` 身份保留项目整体，维持首次出现的顺序及单项键。
- `PasswordListContentSupport.kt` 的仅本地和始终展开路径使用项目分组。
- `PasswordGroupingProjection.kt` 先完成原生结果覆盖、唯一性及边界校验，再按项目整理展开结果；Rust/JNI 本身未修改。
- `StackedPasswordGroup.kt` 只展开不同项目之间的堆叠；一个项目仍走现有多密码卡片路径。混合堆叠按项目拆分并复用已有组件、点击和选择回调。

只依据包含存储来源的显式项目身份分组，不按标题、账号或密码相同合并独立项目。不修改保存路径、数据库格式、加密、认证或锁定机制，也不迁移或删除数据。历史“保存失败后重试生成两份真实项目”的事务问题另见 `local-create-atomicity-329.md`，不与本次显示缺陷混为一谈。

## 修前对照与修后结果

修前实际编辑器创建两密码项目、给已有单密码项目添加第二条密码，以及直接把完整项目传给卡片组件，共 6 个方法：2 个自动模式对照通过，4 个受影响场景均观察到两张卡片并按“一项目一卡片”断言失败。`red03` 为 1/4 通过（9.592 秒），`existing01` 为 1/2 通过（8.798 秒）。保留原始负向日志，没有把预期失败计为通过。

原 6 项行为契约已保留为仓内回归测试，两版全部通过。7 个编辑器场景的最终观察均为：两条密码行、一个项目、一张卡片，点击解析到原来的两条 ID。
