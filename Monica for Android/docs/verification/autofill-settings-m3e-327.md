# 自动填充与通行密钥设置 M3E 统一（未发布 1.0.327）

2026-11-12，普通版 code12 与 canonical F-Droid code34。两版同步 25 个路径（6 生产、18 资源、1 设备测试），最终字节一致，当前完整 app 源码与各自最后一次构建快照一致。修改保留在工作区，未提交、推送、发布或交付 APK。

## 实现与原因

- 默认来源、KeePass 数据库、Bitwarden 库由表单式下拉框改为分组设置行与 M3E 底部单选面板。域名匹配策略、验证码通知时长复用同一面板。整行单选语义、选中背景与圆角分组一致，长名称允许换行和滚动，标题及关闭按钮固定。
- 顶部状态卡保留摘要，移除重复系统填充按钮；系统、通行密钥、填充行为、匹配和保存分别分组，键盘放在核心配置后。物理密钥开关仍与管理页共用偏好，默认关闭；本页复用分组行，管理页保留原组件。
- 源码核对发现旧页面将 DAO 初始空列表视为库已不存在，可能在偏好先到而列表尚未返回时持久清空默认库。null 又表示全部库，可能扩大默认建议范围。本轮以 null 列表区分加载中，取消读取时自动清理：缺失 ID 保留并显示“所选数据库暂不可用”，单选面板不误勾“全部”。只有用户明确点选才写，来源切换在同一次 DataStore.edit 内遵循原跨来源清理政策。
- 未更改凭据加密、认证、数据库结构或实际库内容。这是设置和默认筛选偏好变更，未改 KeePass 文件或 Bitwarden 服务端。旧加载竞态为源码确认，未做旧 APK 设备负对照。

## 工具问题与清理

本轮 Android 构建和设备测试无失败批次。前期资源生成的古文目录名、FD 英文说明500字符限制、截图 run-as 路径/权限尝试，以及最终截图导出脚本的 Windows 默认编码和文件名过滤错误，均为准备/采证问题；修正后18资源和22图收齐，没有以重跑测试掩盖应用失败。原始回执保留本地。

首轮停止自有用户后 remove-user 返回失败；恢复脚本又识别到切回 Owner 后 density 覆盖仍为420，因而停止执行。再次在 Owner 重置为280并复核自有用户停止状态后，删除同一自有用户成功。最终只余原 user0，font_scale 已恢复1.0，ADB 从采图临时 root 恢复 UID2000，仅关闭本任务启动的 MuMu 实例2，实例0/1和全部数据盘保留，公共 AVD 未使用，Canvas 服务保留。失败及最终成功清理回执均保留。

两版 Git diff 空白检查、25共享文件与新文件检查、FD 327/code34元数据及6个脚本测试通过；两版根中英发行说明、本地 next 和 FD fastlane34 同步。
