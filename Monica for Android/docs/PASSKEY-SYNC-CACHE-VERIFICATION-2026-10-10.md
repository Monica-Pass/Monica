# Passkey 同步范围与兼容标记缓存验证（2026-10-10）

## 问题与修复

在公共 Android 32 虚拟机上，修复前的两个回归测试均失败：本地筛选仍提交 `KeePassCompatibilityIndex(databaseId=null)` 任务；已完成检查的兼容标记在列表离开组合后重新进入时，首帧变回空值。截图中的底部进度条还来自主页面对全局活跃 Bitwarden 账户的状态订阅，与当前 Passkey 本地筛选无关。

- 同步状态根据已恢复的 Passkey 筛选选择账户，本地、KeePass 和 MDBX 范围不显示其他 Bitwarden 账户的进度。Bitwarden 文件夹使用自身所属账户。
- Bitwarden 页面自动同步只在范围内有已解锁账户时启动；“全部”仍可拉取现有云库的新条目，不因当前凭据不可导出而阻止整个云库同步。
- KeePass 刷新先等待筛选恢复，按范围筛选已有数据库，在提交任务前检查可读取性和索引版本。没有目标或索引未变化时不提交空任务；任务按数据库 ID 排队，数据库读取在 IO 线程执行。
- 列表和详情共享最多 512 项的进程内 LRU 展示缓存，正常结果有效期 5 分钟，未知结果最多 5 秒。过期结果在后台复查时继续显示，避免重进时闪空。
- 缓存只保留枚举结果、私钥引用的 SHA-256 指纹及兼容性属性，不保留私钥材料。密钥写入、删除、兼容性参数和锁定会话变化会使相应结果失效。加载期间发生失效时，旧结果不能重新写入缓存。登录签名、实际上传和导出仍实时检查，不使用此展示缓存授权。

单元测试覆盖缓存复用、输入变化、并发加载合并、加载中失效、有效期和容量，以及本地／云库／KeePass 同步范围。设备测试覆盖：

- 从主线程调用刷新入口，本地筛选不提交任务；“全部”且没有 KeePass 数据库时不提交空任务。

- 保持页面可见，删除真实受保护私钥后标记变为不可用；恢复同一密钥引用后重新显示限制原因。
- 前一轮的筛选持久化与真实列表往返回归：本地数据库、Bitwarden 文件夹、MDBX 文件夹，以及初始化读取不能覆盖用户的新选择。
